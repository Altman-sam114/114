# v0.96（Mac 计时筛选上下文与 CI Action 运行时升级）

## 版本号与分配依据

v0.96。用户未指定版本号；当前 `origin/main` 最新完成轮次为 v0.95，本轮按 v0 持续优化阶段的小版本规则自动递增为 v0.96。

## 背景

v0.95 已为 macOS 计时详情待办队列增加全部/分类筛选、筛选数/总数、分类空态双操作，以及通过 `MacDetailSelection` 和唯一 `MacQuickAddRequest` 跳转日程快速新增的状态流。当前非空分类筛选态仍有两个可用性缺口：筛选条之后没有常驻上下文和就地动作，用户需要回到筛选 chip 才能确认或清除当前分类；每个任务行仍重复展示相同分类 badge，增加视觉噪声。

v0.95 GitHub Actions run `30185850571` 的云端 job 日志还显示：Checkout、Upload 和 Post Checkout 出现 Node.js 20 弃用提示，Upload 出现 Node `DEP0040` `punycode` 弃用警告，job 汇总明确指出 `actions/checkout@v4` 与 `actions/upload-artifact@v4` 被强制运行在 Node.js 24。本轮应升级官方 Action 主版本，并用项目契约和真实最新 run 日志共同证明警告已消失。

## 目标

- Mac 计时队列在“已选分类且筛选结果非空”时显示常驻分类上下文条，明确当前分类和筛选数/总数。
- 上下文条提供“新增此分类”和“清除筛选”两个就地动作；新增动作继续复用 v0.95 的 `onAddTaskInCategory` 跨页请求，清除动作只把本地筛选设为 `nil`。
- 上下文条使用宽度自适应横排/纵排布局，按钮有稳定点击区；分类名、数量、动作、选中上下文具备完整 VoiceOver 与 Voice Control 语义。
- 非空分类筛选态的任务行隐藏重复分类 badge；未筛选态及其他复用 `MacTaskRowView` 的页面保持 badge 可见。
- 即使隐藏视觉 badge，任务行整行的可访问标签、提示、selected trait 和 Voice Control 输入标签仍完整包含任务名与分类名。
- 云端快照覆盖非空分类筛选态和 220pt 窄宽上下文条回退，不扩大现有 artifact 文件精确清单。
- `.github/workflows/ci-results.yml` 将 `actions/checkout@v4` 升级为 `actions/checkout@v5`，将 `actions/upload-artifact@v4` 升级为 `actions/upload-artifact@v6`，保留既有 checkout 参数、artifact 名称、内容、失败时上传、保留期和最终状态行为。
- `scripts/verify_project.sh` 增加并输出精确 marker：`CI action Node.js 24 contracts verified.`。
- `scripts/validate_ci_artifact.rb` 增加 `PASS verify_project ci action Node.js 24 contracts`；成功 fixture 包含新 marker。
- 增加 Action 旧版本负向 fixture 和新 marker 缺失负向 fixture，确保契约不会放行回退版本或缺少证明的结果包。
- 最新 `origin/main` 云端 run 的完整 job 日志不再出现 Node.js 20 和 `punycode` 弃用警告。

## 非目标

- 不改变任务筛选算法、任务顺序、最多展示 7 项的现有规则或计时选择行为。
- 不改 v0.95 的 `MacQuickAddRequest` 身份与一次性消费流程，不新建第二套快速新增状态流。
- 不全局隐藏 Mac 日程页、其他详情页或未筛选计时队列中的分类 badge。
- 不升级无关 Action，不调整 runner、Xcode、scheme、destination、CI process version、artifact schema、artifact 名称或保留期。
- 不通过设置 `ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION`、过滤日志、静默警告或忽略警告来伪装升级完成。
- 不引入第三方依赖，不做长 View 文件拆分或无关重构。

## 当前架构依据

- `MacTaskQueueView` 从 `FocusStore.upcomingTasks()` 派生 `upcomingTasks`、`visibleTasks` 和 `taskQueueCountText`，`selectedCategory` 是本地展示状态；本轮继续沿用该边界，不新增持久化字段。
- 任务选择仍调用 `TimerEngine.selectTask(_:)`，运行中禁止切换的行为不变。
- v0.95 已通过 `onAddTaskInCategory` 把分类新增意图交给 `MacDetailSelection.requestQuickAdd(category:)`，再由 `MacScheduleDetailView` 一次性消费；上下文条必须复用此回调。
- `MacTaskRowView` 同时被计时队列和日程视图复用，当前分类 badge 与整行可访问语义位于同一组件。应新增仅控制视觉 badge 的兼容参数，并保持默认值为显示，避免影响其他调用端。
- `scripts/render_mac_snapshots.swift` 已用 `产品`、`工程`、`复盘` 分类种子数据渲染正常详情，并将额外分类空态和 220pt 检查写到 `/tmp`，但只把既有正式 PNG 写入 artifact manifest。本轮沿用此模式覆盖非空 `产品` 分类和窄宽上下文，不新增 artifact entry。
- `.github/workflows/ci-results.yml` 是唯一云端重验证入口，当前仅使用 `actions/checkout@v4` 和 `actions/upload-artifact@v4` 两个 JavaScript Action；升级后应分别使用官方 Node.js 24 运行时主版本 v5 和 v6。
- `scripts/verify_project.sh` 负责源码/工作流契约、validator 成功 fixture 和负向 fixture；`scripts/validate_ci_artifact.rb` 负责 Agent C 对下载结果包内 `verify_project.log` marker 的结构化复判。

## 状态与展示流

```text
MacTaskQueueView.selectedCategory 非空
  -> visibleTasks 从 upcomingTasks 派生
  -> visibleTasks 非空时显示常驻分类上下文条
  -> 新增此分类：复用 onAddTaskInCategory(selectedCategory)
  -> 清除筛选：selectedCategory = nil
  -> 任务行传入 showCategoryBadge = false
  -> 仅隐藏重复视觉 badge
  -> 整行 accessibilityLabel / Hint / InputLabels 仍包含分类

selectedCategory 为空
  -> 不显示上下文条
  -> 任务行 showCategoryBadge 使用默认 true
  -> 现有未筛选视觉和语义保持不变

selectedCategory 非空但 visibleTasks 为空
  -> 继续使用 v0.95 MacTimerCategoryEmptyStateView
  -> 不叠加非空上下文条，避免重复双操作
```

## 实现步骤

1. Agent B 开始前执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`，确认 HEAD 与最新 `origin/main` 一致；检查工作区，只保留并绝不提交既存用户文件 `md/1.md`、`md/通用云端迭代升级提示词.md`。
2. 在 `MacTimerDetailView.swift` 为非空筛选态增加职责单一的分类上下文 View。上下文至少显示分类 badge/名称与 `visibleTasks.count/upcomingTasks.count`，并提供新增、清除回调；不要复制筛选数据或持有第二份 `selectedCategory`。
3. 用 `ViewThatFits(in: .horizontal)` 或项目现有等价模式实现上下文动作横排优先、窄宽纵排回退。按钮保持至少 36pt 高度、稳定的最小宽度/可点击区域、单行或合理缩放，避免分类长名、数量和按钮互相遮挡。
4. “新增此分类”调用现有 `onAddTaskInCategory(selectedCategory)`；“清除筛选”只设置 `self.selectedCategory = nil`。两个动作都提供包含分类名的 `.accessibilityLabel`、`.accessibilityHint` 与多组 `.accessibilityInputLabels`。
5. 仅在 `selectedCategory != nil && !visibleTasks.isEmpty` 时插入上下文条。分类空态继续使用 v0.95 的 `MacTimerCategoryEmptyStateView`，全局无待办空态保持不变。
6. 为 `MacTaskRowView` 增加命名明确、默认值为 `true` 的视觉 badge 控制参数，例如 `showsCategoryBadge`。只条件化 `Label(task.category, ...)` 的视觉渲染；不要条件化 `categoryPreset` 色彩、整行 `.accessibilityLabel`、`.accessibilityHint`、`.accessibilityInputLabels` 或 selected trait。
7. 计时队列调用 `MacTaskRowView` 时，根据是否存在选中分类决定 badge 是否显示；日程页等其他调用端依靠默认参数继续显示分类 badge。筛选态行仍保留截止时间等次级元数据，布局不得因 badge 隐藏而留下异常空隙。
8. 扩展 `scripts/render_mac_snapshots.swift`：使用既有 `产品` 分类种子数据渲染非空筛选详情，断言非空、无缺失控件占位；另直接渲染上下文 View 的 220pt 窄宽版本，覆盖纵排回退。额外图片只用于云端运行期检查，沿用 v0.95 模式，不加入正式 snapshot manifest 或 artifact index。
9. 在 `scripts/verify_project.sh` 增加 Mac 计时非空筛选上下文契约，验证显示条件、筛选数/总数、新增/清除接线、视觉 badge 条件化、默认兼容参数、完整可访问语义和两条快照路径。可扩展 v0.95 的 `Mac timer category queue contracts verified.`，但不得削弱现有检查。
10. 将 workflow 的 Checkout 精确升级为 `actions/checkout@v5`，Upload 精确升级为 `actions/upload-artifact@v6`；保持 `fetch-depth: 2`、`if: always()`、artifact `name/path`、`if-no-files-found: error` 和 `retention-days: 14` 不变。
11. 在 `scripts/verify_project.sh` 增加可对 workflow 文本或临时副本执行的 Action 版本契约：必须同时存在 `actions/checkout@v5` 与 `actions/upload-artifact@v6`，并拒绝这两个 Action 的旧主版本。成功后输出且只输出精确 marker `CI action Node.js 24 contracts verified.`。

## 验收标准

- 选中有任务的分类后，Mac 计时队列在筛选条下持续显示当前分类及筛选数/总数，并可就地新增此分类或清除筛选。
- 新增动作仍切到日程、预填同一分类并聚焦标题；同一 quick-add 请求仍只消费一次。清除筛选不修改或删除任何任务。
- 非空筛选态任务行不重复显示分类 badge；清除筛选后 badge 恢复，Mac 日程等其他复用处始终保持现有 badge。
- badge 隐藏时，VoiceOver 仍读出任务名、分类名和选中/运行状态，Voice Control 仍可使用任务名或分类语义定位；运行中不可切换提示和 selected trait 不回归。
- 常规宽度使用紧凑横排，220pt 窄宽使用纵排或等价无重叠回退；长分类名、数量和动作不截断到不可辨认。
- workflow 精确使用 `actions/checkout@v5` 与 `actions/upload-artifact@v6`，旧版本负向 fixture 分别按预期失败。
- 新 marker 存在，marker 缺失 artifact fixture 被 validator 拒绝，validator 输出所有要求的 PASS。
- 最新云端 run 成功，Mac/iOS build 均成功；完整 job 日志不含 Node.js 20 或 `punycode`/`DEP0040` 弃用警告。
- README、测试规范、核心流程、流程图和更新日志与真实实现及最终云端结果一致。

## 风险

- `MacTaskRowView` 是跨页面复用组件；视觉参数默认值错误会让日程页分类信息消失。
- 隐藏 badge 时若同时移除分类相关 modifier，会造成 VoiceOver/Voice Control 语义回归；视觉条件与辅助功能语义必须分离。
- 上下文条与 v0.95 分类空态同时渲染会重复动作；显示条件必须限定非空筛选结果。
- `ViewThatFits` 子 View 若依赖不稳定 intrinsic size，220pt 下可能截断或重叠；云端窄宽快照必须直接覆盖该组件。
- Action 主版本升级可能改变上传行为或默认隐藏文件处理；本轮 artifact 身份、内容和精确清单复判不可省略。
- workflow 静态 marker 只能证明版本声明，不能证明真实 runner 日志无警告；Agent C 必须同时复核最新 run 完整日志。

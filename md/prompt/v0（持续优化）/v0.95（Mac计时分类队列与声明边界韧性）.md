# v0.95（Mac 计时分类队列与声明边界韧性）

## 版本号与分配依据

v0.95。人工未指定版本号；当前最后完成轮次为 v0.94，本轮自动递增。

## 背景

v0.94 已补齐 iOS 计时分类空态新增入口。macOS 计时详情的待办队列仍直接展示全部任务，没有分类筛选、筛选计数或分类空态；用户必须先切到日程页才能按分类处理待办。同时，v0.94 云端失败暴露 `scripts/verify_project.sh` 的通用源码切片 helper 仍依赖 Swift 声明的 `private` 修饰符，访问级别调整会触发与行为无关的假失败。

## 目标

- Mac 计时待办队列增加“全部/分类”筛选，复用 `TaskCategoryPreset.prioritizedFilterOptions`。
- 标题显示当前结果数/总数；再次点击已选分类可清除。
- 选中分类但无待办时显示明确空态，提供“新增此分类”和“清除筛选”。
- “新增此分类”通过 `MacDetailSelection` 发出一次性请求，切换到日程页，预填分类并聚焦快速新增标题。
- 日程页消费请求后复用现有 `prepareQuickAdd(_:)`，避免重复状态流。
- 保持快照脚本直接构造 `MacTimerDetailView()` 和 `MacScheduleDetailView()` 的兼容性。
- 三个通用 accessibility helper 的起点和七个调用端边界不再依赖 `private`。
- 新增云端 marker：`Mac timer category queue contracts verified.` 与 `Declaration boundary resilience contracts verified.`。
- validator 增加两个对应 PASS，并分别增加 marker 缺失负向 fixture。

## 非目标

- 不改 iOS 计时页、`TimerEngine`、`FocusStore` 持久化、共享模型、通知、Live Activity、StoreKit 或 EventKit。
- 不新增第三方依赖，不新增第二套快速新增实现。
- 不全局重写其余 50 余处源码 marker，不扩大为验证脚本解析器重构。
- 不删除任务、文件或旧实现。

## 架构与状态流

`MacDetailSelection` 是详细窗口现有导航状态，新增一次性 quick-add category 请求仍属于导航/UI 状态，不进入 `FocusStore`。

```text
MacTaskQueueView 选择分类
  -> 由 store.upcomingTasks() 派生筛选结果与计数
  -> 分类空态点击“新增此分类”
  -> MacDetailSelection.requestQuickAdd(category:)
  -> selectedSection = .schedule
  -> MacScheduleDetailView 消费唯一请求
  -> selectedCategory 同步分类
  -> 复用 prepareQuickAdd(_:) 预填颜色并聚焦标题
  -> 清空请求，避免重绘或再次进入页面时重复执行
```

计时状态仍只由 `TimerEngine` 管理，任务仍只由 `FocusStore` 提供。

## 实现步骤

1. 同步最新 `origin/main`，确认在 `main` 且只存在两份禁止提交的用户未跟踪文档。
2. 在 `MacDetailSelection` 增加带唯一 id 的一次性分类 quick-add 请求、请求方法和消费方法。
3. `MacDetailContentView` 向计时页传入请求回调，向日程页传入当前请求和消费回调。
4. `MacTimerDetailView` / `MacTaskQueueView` 增加本地筛选状态、派生结果、当前/总数、分类筛选条和分类空态双操作。
5. 复用现有 Mac 分类筛选组件时，仅提升必要类型的可见性；空态文案必须说明会转到日程快速新增，不能复用“左侧快速新增”的错误上下文。
6. `MacScheduleDetailView` 通过带 id 的请求在挂载后只消费一次，并调用现有 `prepareQuickAdd(_:)`；请求为空时保持原行为。
7. 新参数提供默认值或兼容初始化器；保留原计时详情正常队列快照，云端脚本另行渲染零待办分类和 220pt 窄宽空态，覆盖双操作与纵排回退且不增加 artifact 文件数量。
8. `scripts/verify_project.sh` 增加 Mac 计时队列、筛选计数、空态、跨页请求、一次性消费和快照兼容契约，输出 `Mac timer category queue contracts verified.`。
9. 将 `assert_chip_accessibility`、`assert_preset_picker_accessibility`、`assert_calendar_day_accessibility` 的起点改为不含访问修饰符的 `struct` marker；七个调用端结束边界同样去除 `private` / `@MainActor private` 耦合，并输出 `Declaration boundary resilience contracts verified.`。
10. `scripts/validate_ci_artifact.rb` 增加两个 marker 复判；成功 fixture 加入 marker；两个独立负向 fixture 删除各自 marker 后必须失败。
11. 同步 README、`update_log.md`、`md/test/test.md`、`md/flow/flow.md` 和 `md/flow/flowchart.md`。
12. 提交 `v0.95: 增强Mac计时分类队列与CI边界`，直推 `origin/main`，只走 GitHub Actions 和最新 artifact 验收。

## 验收标准

- Mac 计时队列可按全部/分类筛选，再次点击已选分类可清除。
- 标题在筛选时显示 `结果数/总数`，空态不留空白列表。
- 分类空态的新增动作切到日程，分类被预填且标题获得焦点；同一请求只消费一次。
- 清除筛选不删除或修改任务。
- VoiceOver / Voice Control 包含分类名、数量、选中状态和操作名称。
- 快照直接构造路径保持可编译。
- 三个 helper 起点和七个调用边界不依赖访问级别。
- artifact validator 输出 `PASS verify_project mac timer category queue contracts`、`PASS verify_project declaration boundary resilience contracts`、`PASS manifest overall outcome`、`PASS mac build succeeded`、`PASS ios build succeeded`。
- 两个 marker 缺失负向 fixture 均按预期失败。

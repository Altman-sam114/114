## 背景

- iOS `TimerView` 已使用本地 `selectedTaskCategory` 从 `FocusStore.upcomingTasks()` 派生 `filteredUpcomingTasks`，并通过 `taskPickerCountText` 展示筛选数/总数；分类筛选不持久化，也不参与 `TimerEngine` 状态机。
- 当前 `TimerSelectedTaskCategorySummaryView` 在选中分类后无条件出现，仅提供清除动作；当筛选结果为空时，它会与已有 `TimerTaskCategoryEmptyView` 同时出现，形成重复上下文和重复清除入口。
- 当前 `TaskRow` 总是渲染 `TimerTaskCategoryBadge`。分类筛选态中每一行重复显示相同分类，压缩任务标题和截止时间空间；整行的 accessibility label、hint、input labels 和 selected trait 已独立包含分类与选择/运行状态，可将视觉 badge 与辅助功能语义分离。
- `TimerView` 已有 `showingCategoryEditor` sheet，且 `TaskEditorView(initialCategory: selectedTaskCategory)` 已支持当前分类预填。新增此分类只需复用该状态流；保存后 `FocusStore` 更新会让派生列表和计数刷新，`selectedTaskCategory` 保持不变。
- v0.96 已让 Mac 非空分类筛选态具备分类上下文、筛选数/总数、新增/清除双操作和重复 badge 隐藏。本轮只对齐 iOS 的展示与交互，不复制 Mac 导航或 quick-add 状态。
- `scripts/validate_ci_artifact.rb` 当前必需接收解包目录以及 commit/run/attempt，只复判解包内容的身份、结构和本地元数据；它不接受原始 ZIP，也不能证明下载归档与 GitHub API 提供的大小和 SHA-256 digest 一致。
- `actions/upload-artifact@v6` 的 GitHub Actions artifact API 已提供归档 `size_in_bytes` 和 `digest`。Agent C 应在信任解包内容前保留原始 ZIP，并将 API 外部元数据传给 validator；包内自报数据不能替代 API digest。

## 本轮目标

### 目标 1：iOS 计时非空分类筛选上下文

- 仅当 `selectedTaskCategory != nil` 且 `filteredUpcomingTasks` 非空时显示分类摘要；摘要展示分类、筛选数/总数，并提供“新增此分类”和“清除筛选”两个动作。
- 当已选分类没有可启动待办时，只显示既有 `TimerTaskCategoryEmptyView`，不得再叠加非空摘要；全局无待办空态保持不变。
- 摘要使用 `ViewThatFits(in: .horizontal)` 或项目现有等价方式，在常规宽度横排、窄屏或大动态字体下纵排，保证文本、计数和两个按钮不重叠。
- “新增此分类”只设置现有 `showingCategoryEditor = true`，继续由现有 sheet 将 `selectedTaskCategory` 作为 `TaskEditorView.initialCategory`；“清除筛选”只调用现有 `clearTaskCategoryFilter()`。
- 保存新增待办并返回计时页后，当前分类筛选保持，筛选数/总数通过 `FocusStore` 现有派生数据自动刷新；不新增 toast、导航请求或第二套编辑状态。
- 为 iOS `TaskRow` 增加命名明确、默认值为 `true` 的视觉 badge 参数，例如 `showsCategoryBadge`。计时分类筛选态传 `false`，未筛选态和其他默认调用保持显示。
- 隐藏视觉 badge 时，整行仍必须保留任务名、分类名、选中状态、运行中不可切换提示、selected trait 和 Voice Control input labels；截止时间等次级信息保持可见且不留下异常空隙。

### 目标 2：GitHub artifact 原始 ZIP 完整性

- 扩展 `scripts/validate_ci_artifact.rb`，增加成组可选参数：

  ```text
  --archive ZIP
  --archive-size BYTES
  --archive-digest sha256:HEX
  ```

- 三个归档参数必须全有或全无。只提供其中一个或两个时必须以参数错误拒绝，并清楚指出缺失项；现有不传任何归档参数、只验证解包目录的调用必须保持完全兼容。
- 提供完整参数组时，validator 必须对同一个真实归档文件执行以下检查，并输出精确结果：
  - `PASS artifact archive byte count`：本地 ZIP 实际字节数与 GitHub API `size_in_bytes` 完全一致。
  - `PASS artifact archive sha256 digest`：使用标准 SHA-256 对本地 ZIP 实际内容计算摘要，与 API `digest` 的 `sha256:HEX` 完全一致。
  - `PASS artifact archive zip integrity`：归档可由标准 ZIP 完整性检查读取，所有 entry 结构完整且命令成功；不得仅依据扩展名或 magic bytes 放行。
- 参数输入需校验：archive 必须为普通文件，size 必须为正整数，digest 必须匹配 `sha256:` 加 64 位十六进制。SHA-256 使用 Ruby 标准库 `Digest::SHA256`；ZIP 检查使用参数数组调用系统 `unzip -t` 或等价安全方式，不拼接 shell 字符串，不引入第三方 gem。
- 归档检查与现有解包目录检查属于同一次 validator 结果；任一归档检查失败均返回非零，且不得削弱任何既有 manifest/index/run context/JUnit/log/build/snapshot 检查。
- `scripts/verify_project.sh` 完成源码与 fixture 契约后输出精确 marker：`CI artifact archive integrity contracts verified.`。
- `scripts/validate_ci_artifact.rb` 必须复判该 marker，并输出精确检查名：`PASS verify_project ci artifact archive integrity contracts`。
- 增加四类独立负向 fixture，均只操作 `mktemp` 创建的临时文件或目录：
  - `negative_artifact_archive_digest_fixture`：在保持归档字节数不变的前提下修改至少一个字节，仍传原 API size/digest，必须出现 `FAIL artifact archive sha256 digest`。
  - `negative_artifact_archive_size_fixture`：截断 ZIP，仍传原 API size，必须出现 `FAIL artifact archive byte count`。
  - `negative_artifact_archive_zip_fixture`：构造非 ZIP 文件，并传入该文件真实 size 与匹配 SHA-256，使 byte count 和 digest 可通过，但必须出现 `FAIL artifact archive zip integrity`。
  - `negative_ci_artifact_archive_integrity_marker_fixture`：从成功 artifact fixture 的 `verify_project.log` 移除新 marker，必须出现 `FAIL verify_project ci artifact archive integrity contracts`。
- 成功 artifact fixture 必须包含新 marker，并创建一个真实可通过 size、digest 和 ZIP 结构校验的归档；四类负向 fixture 的失败原因必须分别可定位，不能只检查“任意失败”。

## 当前架构依据

- `TimerView.selectedTaskCategory` 是 iOS View 的瞬时筛选状态；`upcomingTasks` 与 `filteredUpcomingTasks` 均从 `FocusStore` 读取并派生。筛选与摘要继续留在 View 层，不新增 Store 字段。
- `TimerEngine.selectTask(_:)` 仍是选择当前计时任务的唯一入口；运行中禁止切换与计时主控行为保持不变。
- `TimerView` 的 `.sheet(isPresented: $showingCategoryEditor)` 已构造 `TaskEditorView(initialDueDate: ..., initialCategory: selectedTaskCategory)`；`TaskEditorView.init` 使用 `task?.category ?? initialCategory ?? "工作"`，现有保存流程写回 `FocusStore` 后 dismiss。
- `TaskRow` 的视觉 `TimerTaskCategoryBadge` 位于内部元数据 HStack，但整行辅助功能语义在外层单独构造。新增参数只控制 badge View 是否渲染，不得控制整行语义。
- `scripts/verify_project.sh` 负责静态源码契约、成功 fixture、负向 fixture 和 marker 生成；`scripts/validate_ci_artifact.rb` 负责 Agent C 对真实下载结果包及可选原始 ZIP 做结构化复判。
- `.github/workflows/ci-results.yml` 仍是唯一云端验证入口；它继续上传未加密 artifact。归档摘要必须来自 GitHub Actions artifact API，而不是 workflow 在包内生成的自报字段。

## 状态流与验收数据流

```text
selectedTaskCategory == nil
  -> 不显示分类摘要
  -> TaskRow.showsCategoryBadge 使用默认 true
  -> 现有未筛选队列行为不变

selectedTaskCategory != nil && filteredUpcomingTasks 非空
  -> 显示分类 + filtered/total + 新增/清除上下文
  -> TaskRow(showsCategoryBadge: false)
  -> 仅隐藏重复视觉 badge
  -> 整行 accessibility 继续包含分类与选择/运行状态
  -> 新增：showingCategoryEditor = true
  -> 现有 sheet 以 selectedTaskCategory 预填 TaskEditor
  -> 保存写回 FocusStore，筛选保持并自动刷新计数

selectedTaskCategory != nil && filteredUpcomingTasks 为空
  -> 只显示现有 TimerTaskCategoryEmptyView
  -> 不显示非空摘要，不形成重复动作

GitHub API artifact metadata
  -> id/name/expired/size_in_bytes/digest 与最新 run 对齐
  -> 下载到唯一 *.part，失败自动重试
  -> 初步核对 size + SHA-256 + unzip -t
  -> 目标 ZIP 不存在时同文件系统原子改名
  -> 解包到全新目录
  -> validator(解包目录 + ZIP + API size/digest + commit/run/attempt)
  -> 归档完整性 PASS + 既有身份/结构/build PASS
```

## 风险

- 摘要条件若仍只判断 `selectedTaskCategory`，会在空结果时与空态重复；必须同时判断 `filteredUpcomingTasks` 非空。
- `TaskRow` 视觉参数默认值或调用条件错误会让未筛选计时页的分类 badge 消失；参数必须默认 `true`。
- 若隐藏 badge 时连带移除外层 accessibility modifier，会造成 VoiceOver、Voice Control、selected trait 或运行提示回归；视觉与语义必须独立。
- TaskEditor sheet 打开时若先清除筛选，`initialCategory` 会丢失且保存返回后无法保持上下文；新增动作不得改 `selectedTaskCategory`。
- GitHub API digest 是压缩归档摘要，不等同于解包目录内容摘要；必须对原始下载 ZIP 字节计算，不能对解包文件重新打包后比较。
- ZIP 截断或篡改可能同时触发多个失败；负向 fixture 仍必须断言目标失败行，尤其非 ZIP fixture 要使用自身匹配的 size/digest 隔离结构失败。
- `unzip -t` 若通过 shell 字符串调用会产生路径注入和空格问题；必须使用安全参数数组并检查真实 exit status。
- 只验证 size 会漏过等长篡改，只验证 digest 会漏掉错误的 API 绑定，只验证 magic bytes 会漏过中央目录损坏；三项检查不可互相替代。
- `.part` 或最终文件被覆盖会混淆 run 身份并破坏审计证据；缓存目录和目标文件必须唯一且默认拒绝覆盖。

## 2. 背景

`scripts/verify_project.sh` 的 Mac core 验证通过独立的 `xcrun --sdk macosx swiftc` 命令编译共享模型、Store、扩展和 `scripts/test_mac_core.swift`。当前 core 命令在约 5155-5161 行只传入：

```text
ChronoFocus/Models/AppModels.swift
ChronoFocus/Services/FocusStore.swift
Shared/SharedExtensions.swift
scripts/test_mac_core.swift
```

但 `scripts/test_mac_core.swift` 的 `runTimerEngineBoundaryTests` 在第 178 行直接构造 `TimerEngine`，并在第 291 行以后实现 `TimerNotificationServicing` 和 `TimerLiveActivityServicing` 的 fake。`TimerEngine.swift` 依赖这两个协议，而协议定义在 `TimerPlatformServices.swift`。因此云端 core 编译阶段报：

```text
scripts/test_mac_core.swift:178:22: error: cannot find 'TimerEngine' in scope
```

失败日志还确认 `verify_project.sh` 在该 core 编译命令处退出；随后 workflow 的 `PROJECT_VERIFY_OUTCOME` 为 `failure`。同一脚本的 Mac snapshot 编译源列表已经包含 `TimerEngine.swift` 和 `TimerPlatformServices.swift`，本轮只需让 Mac core 编译命令拥有同样的共享计时依赖。

## 5. 当前架构依据

### 5.1 Mac core 的真实依赖边界

- `ChronoFocus/Models/AppModels.swift` 提供 `TimerMode`、`TimerSettings`、`ActiveTimerSnapshot`、`FocusTask` 等共享类型。
- `ChronoFocus/Services/FocusStore.swift` 是任务、设置、会话、计划和活跃快照的共享仓库。
- `ChronoFocus/Services/TimerPlatformServices.swift` 提供 `TimerNotificationServicing` 与 `TimerLiveActivityServicing` 抽象；Mac core 测试通过 fake 实现它们，不依赖 AppKit 或真实平台服务。
- `ChronoFocus/Services/TimerEngine.swift` 是唯一计时状态机，`TimerEngine` 初始化需要 `FocusStore` 和上述两个平台服务协议，并实现选择、启动、暂停、停止、完成和失效任务边界。
- `scripts/test_mac_core.swift` 在 `@MainActor` 下运行 Store、分类、计划、统计、startable task 和 TimerEngine boundary 测试；它不是产品逻辑的第二实现。
- `Shared/SharedExtensions.swift` 提供跨平台共享扩展。Mac core 仍通过直接 `swiftc` 编译，不改变 Xcode target 的平台边界。

### 5.2 当前脚本的可复用基准

- Mac snapshot 的 `swiftc` 命令已经按 `AppModels.swift`、`FocusStore.swift`、`TimerEngine.swift`、`TimerPlatformServices.swift`、`SharedExtensions.swift` 顺序接入共享计时依赖；core 命令应复用这两个缺失路径。
- `scripts/verify_project.sh` 之前已经通过静态 contract 检查和 snapshot 编译引用 `TimerEngine.swift`；本轮不需要新增静态 marker，只修正运行 core 测试的输入源集合。

## 2. 背景

ChronoFocus 的 iOS `ScheduleView` 和 macOS `MacScheduleDetailView` 已有分类筛选。任务列表在选择 `selectedCategory` 后会缩小到当前分类，但日期格的待办数量仍可能直接遍历全部任务：

- iOS `ChronoFocus/Views/ScheduleView.swift` 的 `visibleTasks` 已同时按选中日期范围和 `selectedCategory` 过滤，`taskCount(in:)` 也有分类上下文；但 `taskCount(on:)` 当前只按 `dueDate` 和日期匹配 `store.tasks`，没有应用 `selectedCategory`。
- iOS `CalendarDayButton` 的可访问标签会读出日期、待办数、选中/非本月状态，但待办数没有说明它是否属于当前分类筛选。
- macOS `MacScheduleDetailView` 的 `selectedCategory` 由 `MacTaskListPanelView` 绑定管理；`MacCalendarPanelView` 目前独立持有日期/范围状态，日期格 `taskCount(on:)` 直接统计 `store.tasks`，没有接收同一个分类上下文。
- macOS `MacCalendarDayCell` 的标签同样读出全量日期计数和日期状态，无法保证与当前分类列表的语义一致。

本轮只解决 UI 派生数据和辅助功能上下文的一致性。分类筛选仍是 View 层的瞬态状态，任务数据仍由 `FocusStore` 提供，计时仍由 `TimerEngine` 管理。

## 3. 本轮目标

### 3.1 核心行为

1. iOS 日程周条和月格的日期计数在未筛选时保持现有全量任务语义；选中分类后，日期格只计算同一日期且 `task.category == selectedCategory` 的任务。
2. macOS 日程周/日/月日期格使用与 macOS 任务列表相同的 `selectedCategory` 上下文。父 `MacScheduleDetailView` 只有一个分类筛选源，日历面板通过绑定接收它，不创建第二个独立分类状态。
3. macOS 日历面板如继续显示范围计数、范围空态或范围内任务行，相关派生结果必须与日期格使用同一分类上下文，不能出现日期格显示分类内数量而范围列表仍显示全量任务的矛盾。只调整为达成上下文一致所必需的局部派生逻辑。
4. 切换分类、再次点击已选分类清除筛选、点击“全部”、改变日期或范围后，日期格计数、范围计数、列表和空态立即反映当前状态，不保留旧分类数量。
5. 保留现有日期匹配边界：日期格继续以带 `dueDate` 的任务和 `Calendar.current.isDate(_:inSameDayAs:)` 计数；不要因为本轮分类修复而把日期格改成按创建时间计数。日/周/月范围和无 `dueDate` 任务在列表中的现有语义保持不变。
6. 保留现有任务计数的完成/启用语义。本轮不要额外引入“只统计未完成”或“只统计可启动”的新规则；日期格只增加当前分类谓词。

### 3.2 日期格可访问语义

1. iOS `CalendarDayButton` 与 macOS `MacCalendarDayCell` 的 VoiceOver 标签必须让用户知道日期计数属于哪个上下文：
   - 未筛选时继续包含日期、全量日期待办数和已有的选中/非本月状态。
   - 选中分类时包含当前分类名称和该分类在该日期的计数，例如“8月9日，当前筛选工作分类，2项待办，已选中”；具体措辞可按现有中文风格调整，但不能只读出无上下文的全量数字。
2. 日期按钮的选择提示、`selected` trait、非本月状态和 Voice Control 日期输入标签必须保留。Voice Control 输入标签继续以日期为主，不能为了显示分类上下文而渲染重复的可见文字。
3. 可访问语义必须和视觉计数来自同一个派生值，不能视觉上显示分类计数而辅助功能仍读出全量计数，或反之。
4. 长分类名、动态字体和窄宽下，日期按钮标签不改变固定日期格布局，不造成日期、圆点、状态文字或按钮互相遮挡。日期格仍保持现有稳定点击区域和视觉样式。

### 3.3 分类上下文边界

- iOS 继续使用 `ScheduleView` 的 `selectedCategory`，不要把筛选状态提升到共享模型。
- macOS 让 `MacScheduleDetailView` 把 `$selectedCategory` 传给 `MacCalendarPanelView`；`MacTaskListPanelView` 与日历面板共享同一绑定，不复制筛选状态。
- 分类比较沿用现有任务列表的精确比较规则，不在本轮新增分类规范化、排序或持久化。
- 日期范围仍由各自 View 的 `selectedDate` / `calendarMode` 和现有 `Calendar.current` 派生；不把日期选择写入 `FocusStore`。
- `FocusStore` 继续是任务数据唯一来源；不新增散落的 `UserDefaults` 写入，不修改 `upcomingTasks()`、`startableTasks()` 或持久化格式。
- `TimerEngine`、计时接力、当前任务、计划生成、通知和 Live Activity 不属于本轮范围。

## 5. 当前架构依据

### 5.1 iOS

- `ScheduleView` 持有 `selectedDate`、`calendarMode` 和 `selectedCategory`。
- `visibleTasks` 通过 `isTaskInSelectedRange(_:)` 和 `matchesSelectedCategory(_:)` 派生列表，并按现有 due date/createdAt 规则排序。
- `weekStrip` 和 `monthGrid` 将 `taskCount(on:)` 传给 `CalendarDayButton`；当前日期计数只遍历带 `dueDate` 的 `store.tasks`。
- `taskCount(in:)` 供列表总数、分类 chip 和摘要使用；不要用日期格计数函数替代范围计数函数。
- `CalendarDayButton` 已具备日期格式化、选中/非本月状态、hint、selected trait 和 Voice Control labels，应在其现有边界中补齐分类上下文。

### 5.2 macOS

- `MacScheduleDetailView` 的 `selectedCategory` 同时用于快速新增上下文和 `MacTaskListPanelView` 的筛选。
- `MacCalendarPanelView` 持有自己的 `selectedDate` 和 `calendarMode`，当前通过 `onAddTaskAtDate` 回调把日期交给父视图；它不应拥有第二份分类筛选状态。
- `MacCalendarPanelView.visibleTasks` 使用现有日期范围规则；`MacCalendarDayCell` 负责日期视觉、标签、hint、selected trait 和 Voice Control labels。
- `MacTaskListPanelView` 已使用 `store.upcomingTasks()` 和精确分类匹配；本轮只把相同上下文接到日历面板，不改 `FocusStore` 查询边界。

### 5.3 云端验证

- `.github/workflows/ci-results.yml` 是 `main` push 后唯一正式 CI 入口，运行 Static checks、`scripts/verify_project.sh`、macOS build、iOS generic build、Mac snapshots、结果包生成和 artifact upload。
- 当前正式 artifact 保持 manifest、artifact index、run context、failure summary、JUnit/等价摘要、主日志、两端 build 日志、两端 `.xcresult`、五张正式 Mac PNG 和 snapshot manifest 的既有结构。
- 现有日期格辅助功能源码检查由 `scripts/verify_project.sh` 的 `assert_calendar_day_accessibility` 覆盖，现有云端日志包含 `Category chip accessibility contracts verified.`。本轮若扩展检查，必须沿用稳定的声明边界并保持既有负向 fixture 的单失败隔离。
- `scripts/validate_ci_artifact.rb` 的第四模式已经用于把云端 artifact 与包外 API 身份、原始 ZIP 和自建解包目录绑定；本轮不降低该门槛。

## 6. 实现步骤

### 6.1 iOS 日期计数

1. 在 `ChronoFocus/Views/ScheduleView.swift` 的现有日期计数边界内，先保留 `dueDate` guard 和 `calendar.isDate(dueDate, inSameDayAs: date)`，再追加与 `matchesSelectedCategory(_:)` 一致的可选分类判断。
2. 确保 `weekStrip`、`monthGrid` 的 `CalendarDayButton` 都使用这一分类范围一致的计数，不让其中一个入口继续使用全量任务。
3. 让日期格的可访问标签从同一计数和同一 `selectedCategory` 派生；无筛选的现有 label 基础语义尽量保持稳定，选中分类时明确说出分类上下文。
4. 不修改 `isTaskInSelectedRange(_:)` 的 day/week/month 分支，也不把日期格计数错误地改成 `visibleTasks.count`；一个范围可能包含多个日期。

### 6.2 macOS 分类状态传递

1. 修改 `MacScheduleDetailView` 到 `MacCalendarPanelView` 的局部调用和声明，使日历面板接收父视图的 `@Binding var selectedCategory: String?`。
2. 日历面板的日期格计数、范围计数、范围内任务行和必要的空态上下文使用同一可选分类谓词；未筛选时保留全量行为。
3. 保持 `onAddTaskAtDate` 回调和 `prepareQuickAdd(at:)` 的日期/时分逻辑不变；分类预填仍由父视图当前分类上下文负责，不把它持久化。
4. `MacCalendarDayCell` 的标签与 iOS 采用同一语义原则：日期、当前分类（若有）、该日期分类待办数、选中/非本月状态；日期 hint 和 Voice Control labels 继续可用。
5. 不把 `MacCalendarPanelView` 的日期选择状态提升到父视图，也不让日历面板直接操作 `TimerEngine`。

### 6.3 最小云端合同/快照覆盖（按需要）

1. 优先在现有日期格源码合同中增加明确的分类上下文断言，或沿用现有 `Category chip accessibility contracts verified.` 体系；不要因为本轮目标重复创建大套合同。

3. 任何 marker/validator fixture 修改只能由 Agent B 在本轮相关脚本范围内完成；本提示词创建阶段不修改 `scripts/verify_project.sh` 或 `scripts/validate_ci_artifact.rb`。

## 12. 验收标准

### 12.1 功能与分类一致性

- 未筛选时，iOS/macOS 每个日期格的计数与当前既有全量日期待办语义一致。
- 选中分类时，日期格只计数该分类在该日期的任务；混合分类同日 fixture 能证明全量数与分类数不同且筛选后显示分类数。
- iOS 列表、分类摘要、日期格和日期格 label 使用同一个 `selectedCategory` 上下文；macOS 任务列表、日历面板范围计数/任务行、日期格和 label 使用同一个绑定上下文。

### 12.2 可访问性

- 日期 hint、selected trait、非本月语义和 Voice Control 日期 labels 继续通过源码合同；视觉数字与辅助功能数字来自同一值。
- 日期按钮不因长分类名或动态字体发生明显遮挡、截断或点击区退化。

## 13. 风险与禁止项

- 继续直接使用 `store.tasks` 统计日期格，会让筛选列表与日期数字产生误导；但不能简单使用 `visibleTasks.count`，因为日期格按单日计数，范围列表可能跨多日。
- macOS 若让日历面板复制一个 `selectedCategory`，任务列表和日期格会在切换分类后分叉；必须通过父级同一 `Binding` 传递。
- 若只改变视觉圆点而不改变 accessibility label，VoiceOver 仍会报告全量数字；若只改变 label 而视觉计数未变，也会产生相反矛盾。
- 若把 `selectedCategory` 写入 `FocusStore`、UserDefaults 或 `TimerEngine`，会扩大状态边界并引入跨页恢复副作用；本轮禁止。
- 若把无截止日期任务的创建日规则混入日期格，日/周/月数字会改变既有含义；本轮只增加分类谓词。
- 若修改现有源码合同时依赖跨声明的大段文本，可能破坏稳定切片；应沿用 `source_slice` / `segment_slice` 的现有声明边界。
- 快照 fixture 过多可能改变正式 detail-schedule 布局；优先复用现有同日混合分类 fixture，临时图不进正式 manifest。
- GitHub artifacts API 不提供 `run_attempt`；不得从包内字段自证 attempt，也不得用旧 artifact 名称、digest 或本地输出冒充新证据。
- 禁止本地测试、validator、Swift/Xcode 构建、`xcodebuild`、`simctl`、Simulator、浏览器、删除文件、回滚他人改动、提交用户未跟踪文件、修改无关 CI 安全语义或为了通过而降低门槛。

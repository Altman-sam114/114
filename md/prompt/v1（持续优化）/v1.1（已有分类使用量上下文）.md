# v1.1：已有分类使用量上下文

## 1. 版本号与分配依据

- 版本号：`v1.1`。
- 分配依据：v1.0 已完成已有分类复用和 Run API 证据链；本轮在同一分类录入流程上增加来源/使用量上下文，属于兼容的小步 UI 与云端契约增强，因此递增为 v1.1。
- 固定实现提交信息：`v1.1: 显示已有分类使用量`。
- 提示词路径：`md/prompt/v1（持续优化）/v1.1（已有分类使用量上下文）.md`。
- 分支固定为 `main`，直接 push `origin/main`，只验收最新 HEAD 对应的 GitHub Actions run/artifact。

## 2. 背景

v1.0 的 iOS 待办新增/编辑和 macOS 快速新增已经显示非预设“已有分类”，但选项只有名称与颜色。`FocusStore.taskCategories` 同时合并当前任务和历史 session 分类，用户无法判断某分类仍有多少待办，或它只是历史专注记录。本轮为每个选项派生任务数量；有任务时显示数量，无任务时显示“历史”。

## 3. 目标

1. iOS 与 macOS 每个非预设已有分类增加 `taskCount`，统计 `store.tasks` 中使用同一规范化比较键的全部任务。
2. `taskCount > 0` 时显示紧凑数量；`taskCount == 0` 时显示“历史”，明确仅来自历史 session。
3. folding 继续使用 `en_US_POSIX` 和大小写、变音符号、宽度不敏感选项；近似名称计入同一分类。
4. 使用量不改变 v1.0 的首次出现顺序，不按数量排序。
5. 保持代表色、session-only 草稿颜色回退、selected、重复点击和仅修改表单草稿的边界。
6. VoiceOver 对任务分类读出“<分类>分类，<N>项任务”，对历史分类读出“<分类>分类，仅历史专注记录”；选中状态继续附加“已选中”和 `.isSelected`。
7. Voice Control 保留分类名、`<分类>分类`、`选择<分类>分类`；iOS 点击区至少 44pt，动态字体下名称可换行，数量/历史/checkmark 不重叠。
8. 云端验证新增 `Existing category usage context contracts verified.` marker、validator PASS 和 marker 缺失负向 fixture。

## 4. 非目标

- 不新增或迁移模型字段，不持久化计数，不改变 `FocusStore.taskCategories`。
- 不实现分类管理、重命名、合并、删除、批量重分类或数量排序。
- 不改变 `TimerEngine`、计划生成、统计算法、StoreKit、EventKit 或通知边界。
- 不删除或替换 v1.0 的已有分类复用契约、fixtures、marker 或 validator PASS。
- 不修改 artifact 文件清单、名称、retention、manifest/index 格式或 Run API 第四模式。
- 不读取、编辑、暂存或提交 `md/1.md` 与 `md/通用云端迭代升级提示词.md`。

## 5. 当前架构依据

- `FocusStore.taskCategories` 仍是选项顺序和显示名称来源；`store.tasks` 只用于派生每个规范化 key 的 `taskCount` 与首个匹配任务代表色。
- iOS 实现在 `ChronoFocus/Views/ScheduleView.swift` 的 `TaskEditorView` / `ExistingCategoryOption`。
- macOS 实现在 `ChronoFocusMac/Views/MacScheduleDetailView.swift` 的 `MacExistingCategoryOption`、真实按钮和静态快照 strip；两条渲染路径必须共享同一 option 数据。
- Mac 云端快照种子位于 `scripts/render_mac_snapshots.swift`，应同时覆盖有任务分类和 session-only 分类。
- 云端源码契约位于 `scripts/verify_project.sh`，artifact marker 复判位于 `scripts/validate_ci_artifact.rb`。

## 8. 风险与禁止项

- 数量必须按规范化 key 聚合，而不是按显示字符串精确比较；否则近似分类会显示错误数量。
- session-only 分类必须为 0 并显示“历史”，不能伪造一个任务或从 session 数量替代任务数。
- 不让计数触发排序、保存、自动改色或 View 出现时的数据写入。
- 不依赖颜色传达数量、历史或 selected；长名称、大号动态字体和窄宽度下不得遮挡。
- 默认不删除、不覆盖证据；Agent C 下载使用全新唯一目录和 `.part` 无覆盖改名。

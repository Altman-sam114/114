# v1.3 日程分类接力到计时

## 1. 版本号与分配依据

- 版本号：`v1.3`。
- 分配依据：`md/prompt/README.md` 与 `update_log.md` 的最新完成版本为 v1.2，按同一 v1 持续优化序列递增。
- 本轮角色：Agent A 定义目标；Agent B 基于最新 `origin/main` 实现并直接 push；Agent C 只接受该 commit 最新 GitHub Actions push run 的原始证据。

## 2. 背景

v1.2 已让 iOS/macOS 的长已有分类列表可搜索，并把 Run API 授权来源纳入第四模式复判。当前日程页已有分类筛选、分类摘要、新增与清除操作，计时页也有独立分类筛选和当前任务选择，但用户从日程确认工作上下文后仍需手动切换到计时、重新筛选分类并再次寻找任务。

现有架构已有可复用边界：

- `DashboardView` 持有 iOS `TabView` selection。
- `MacDetailSelection` 已用带 UUID 的 `MacQuickAddRequest` 完成一次性跨页请求与消费。
- iOS/macOS 计时任务列表均从 `FocusStore` 的当前可启动任务重新派生。
- `TimerEngine.selectTask(_:)` 是唯一任务选择入口，并在运行中拒绝切换。

## 3. 目标

1. iOS/macOS 日程分类摘要增加“转到计时”操作，一次进入计时页、恢复该分类筛选并选择该分类首个当前可启动任务。
2. iOS/macOS 日程任务行增加“设为计时待办”操作，一次进入计时页、恢复任务分类并精确选择该任务。
3. 请求为带唯一 UUID 的 View 层瞬态值，消费端只处理当前 id 一次并回调清除。
4. 消费时必须重新查询当前 `FocusStore` 数据：已完成、已停用、已删除或不再可启动的 preferred task 不得被选中。
5. 计时运行中仍允许导航并查看目标分类，但不得替换 `TimerEngine` 当前任务。
6. 接力只完成导航、分类筛选和任务选择，不自动开始计时；开始仍由用户调用现有计时主控。
7. 新增独立云端 contract marker 与 artifact validator PASS，预期完整基线为 `129 PASS / 0 FAIL`。

## 4. 非目标

- 不调用 `engine.start()`，不实现“一键即开始”。
- 不直接写 `engine.selectedTaskID`，不在 View 中制造第二套当前任务或计时状态。
- 不新增模型字段、UserDefaults key、迁移、历史接力记录、深链或跨设备同步。
- 不修改任务排序、分类排序、计划生成、自动开始、通知、StoreKit 或 EventKit 语义。
- 默认不修改 `FocusStore`、`TimerEngine` 或 `AppModels.swift`；现有公开入口足以完成本轮。
- 不改变 artifact 名称、内容清单、process version 或前三种 validator 模式。
- 不读取、编辑、暂存或提交 `md/1.md` 与 `md/通用云端迭代升级提示词.md`。

## 5. 当前架构依据

### 5.1 iOS

- `ChronoFocus/Views/DashboardView.swift` 当前持有 `selectedTab`，适合持有一次性 `TimerHandoffRequest` 并把 request/consume callback 注入 `TimerView`。
- `ChronoFocus/Views/ScheduleView.swift` 已拥有分类摘要、筛选后的任务列表与任务行操作，可通过 callback 发出请求，不直接依赖计时引擎内部状态。
- `ChronoFocus/Views/TimerView.swift` 已持有 `selectedTaskCategory`，且任务点击使用 `engine.selectTask(task)`；接力应复用相同筛选与选择路径。

### 5.2 macOS

- `ChronoFocusMac/Views/MacDetailView.swift` 的 `MacDetailSelection` 已实现唯一 id 请求、切换 section 和按 id 消费的协调器模式。
- `ChronoFocusMac/Views/MacScheduleDetailView.swift` 已通过 callback 处理跨页快速新增，可增加接力 callback 而不直接操作详情窗口控制器。
- `ChronoFocusMac/Views/MacTimerDetailView.swift` 的任务队列已使用分类筛选和 `engine.selectTask(task)`，应负责消费接力请求。

### 5.3 状态边界

- 请求只携带 `id`、规范化前的显示分类字符串和可选 `preferredTaskID`，不持久化。
- `preferredTaskID == nil` 表示分类摘要接力，消费端选择该分类首个当前可启动任务。
- `preferredTaskID != nil` 表示精确任务接力；若该 id 已失效，只保留分类筛选，不回退选择另一任务。
- 非运行态若当前已选任务不属于接力分类且没有合法目标，可通过 `engine.selectTask(nil)` 清除不一致选择；运行态不得清除或替换。

## 6. Agent B 实现步骤

### 6.1 iOS 请求与导航

1. 定义轻量 `TimerHandoffRequest: Identifiable, Equatable`，字段仅为自动生成 `id`、`category`、`preferredTaskID`。
2. `DashboardView` 增加瞬态 request state；向 `ScheduleView` 注入请求 callback，收到后保存 request 并把 `selectedTab` 切到 `.timer`。
3. 向 `TimerView` 注入 request 与按 id 消费 callback；保持现有无参数调用或 Preview 接线可编译。
4. `TimerView` 使用 `.task(id: request?.id)` 或等价 idempotent 入口：设置分类筛选、收起任务列表、从当前可启动任务重新查找目标、仅在非运行态调用 `engine.selectTask(...)`，最后按 id 消费。

### 6.2 iOS 日程入口

1. 分类摘要增加图标+文本命令“转到计时”，携带当前分类且 `preferredTaskID=nil`。
2. 任务行增加熟悉的计时/播放相关 SF Symbol 操作，携带任务分类和任务 id；已完成或已停用任务不可发出可选择请求。
3. 分类摘要三操作使用 `ViewThatFits` 或现有自适应布局，窄屏和动态字体时纵向排列；新操作最小高度 44pt。
4. VoiceOver 标签必须包含分类、任务名与目的；Voice Control input labels 至少含“转到计时”“在计时页查看<分类>分类”“将<任务>设为计时待办”。

### 6.3 macOS 请求与导航

1. 在 `MacDetailSelection` 增加 `MacTimerHandoffRequest`、`requestTimerHandoff(category:preferredTaskID:)` 和按 id 消费方法。
2. 发出请求时保存唯一 request 并把 `selectedSection` 切到 `.timer`；不得覆盖或复用 `MacQuickAddRequest`。
3. `MacDetailView` 把 request 和消费 callback 注入 `MacTimerDetailView`，把请求 callback 注入 `MacScheduleDetailView`。
4. `MacTimerDetailView`/任务队列按与 iOS 相同规则消费：先恢复分类，再从 store 当前可启动任务验证 preferred id，非运行态才使用 `engine.selectTask`，最后按 id 清除。

### 6.4 macOS 日程入口与快照

1. Mac 分类摘要与任务行增加对应接力操作，保留现有新增、清除、完成、启用、编辑、删除语义。
2. 静态快照路径必须显示分类摘要接力入口，且不把 callback 或真实交互逻辑复制成第二套业务实现。
3. `scripts/render_mac_snapshots.swift` 让 `detail-schedule.png` 展示“转到计时”入口，让 `detail-timer.png` 展示产品分类筛选和目标任务 selected 终态；不扩展正式 5 张快照清单。

### 6.5 CI 与结果包复判

1. `scripts/verify_project.sh` 新增结构化源码切片，覆盖两端 request 字段、唯一 id、摘要/任务行接线、导航、store 重新查询、运行中保护、按 id 消费和可访问语义。
2. 明确拒绝接力消费切片中的 `engine.start()`、直接 `selectedTaskID =`、持久化写入或绕过 `engine.selectTask(...)`。
3. 成功时输出精确 marker：`Schedule to timer handoff contracts verified.`。
4. 增加只移除该 marker 的负向 fixture，必须只命中新 contract 失败。
5. `scripts/validate_ci_artifact.rb` 增加 `PASS verify_project schedule to timer handoff contracts`，其余 128 项保持兼容，预期完整基线为 `129 PASS / 0 FAIL`。

## 11. 风险与禁止项

- Tab/SplitView 重建可能重复消费，必须依赖唯一 request id 和按 id 清除。
- 请求发出到消费之间任务可能变化，必须重新查询 store，不能信任旧 task 对象。
- 自动开始会改变用户控制和通知/Live Activity 语义，本轮严禁调用。
- 摘要增加第三个动作容易拥挤，必须采用自适应布局并由云端快照复判。
- 静态快照不能覆盖真实点击过程；该限制必须作为遗留风险，不得冒充交互测试。
- 不回滚失败 commit，不删除失败证据；失败时在 `main` 追加修复并重新走 Agent C。

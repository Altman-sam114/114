# v1.2：已有分类搜索与 Run 来源复判

## 1. 版本号与分配依据

- 版本号：`v1.2`。
- 分配依据：v1.1 已闭环已有分类任务数/历史来源上下文；本轮继续改善长分类列表的选择效率，并在既有 Run API 完整模式中补齐授权触发来源，属于 v1 大版本内兼容增强。
- 固定实现提交信息：`v1.2: 搜索已有分类并复判Run来源`。
- 提示词路径：`md/prompt/v1（持续优化）/v1.2（已有分类搜索与Run来源复判）.md`。
- 协作分支固定为 `main`，直接 push `origin/main`，只验收最新 HEAD 对应的 GitHub Actions run/artifact。

## 2. 背景

### 2.1 长分类列表难以定位

iOS 待办新增/编辑和 macOS 快速新增已展示完整非预设分类、任务数或“历史”，但始终以单行横向列表铺开。分类较多时只能反复横向扫描，缺少名称搜索、结果计数、清除与无结果反馈。

### 2.2 Run 成功尚未证明授权触发来源

validator 已核对 Run API 的 id、attempt、SHA、branch、workflow name/path、status、conclusion 和 repository，但尚未证明事件是 `push`、初始 actor 和 triggering actor 是授权账号，以及被构建提交来自授权 head repository。

## 3. UI 目标

1. 非预设已有分类数量达到 `6` 个时，iOS/macOS 显示独立“搜索已有分类”控件；少于 6 个时保持当前紧凑列表。
2. 查询去除首尾空白后，以 `en_US_POSIX` 执行大小写、变音符号和宽度不敏感 folding，再做名称子串匹配。
3. 空查询恢复全部；结果保持 `store.taskCategories` 首次出现顺序，不按匹配度、数量或名称重排。
4. 搜索只过滤可见 option，不修改 `category`、`accentHex`、任务、session、`FocusStore` 或持久化。
5. 点击结果后保留查询；已选 chip 继续可见时保留 checkmark、selected trait、任务数/“历史”和现有颜色规则。
6. 标题显示“结果数/总数”；无结果时保留搜索控件并显示“没有匹配的已有分类”，不得自动采用查询文本或创建分类。
7. 清除使用 `xmark.circle.fill`；iOS 点击区至少 44x44，VoiceOver/Voice Control 名称为“清除已有分类搜索”。
8. macOS 收到分类筛选摘要或跨页快速新增预填时清空旧查询，避免目标分类被隐藏。
9. Mac 真实与静态快照路径共享同一过滤结果；快照覆盖至少 6 个非预设分类和非空搜索状态。

## 4. CI 目标

在现有 `--run-metadata` 第四模式新增四项独立复判：

- `event == "push"` -> `PASS workflow run metadata event`
- `actor.login == "Altman-sam114"` -> `PASS workflow run metadata actor`
- `triggering_actor.login == "Altman-sam114"` -> `PASS workflow run metadata triggering actor`
- `head_repository.full_name == "Altman-sam114/114"` -> `PASS workflow run metadata head repository`

完整 Run API 模式由 10 项增至 14 项。`repository.full_name` 继续证明 workflow 所属仓库，`head_repository.full_name` 独立证明提交来源；`actor` 与 `triggering_actor` 同时约束初始执行和 rerun。

项目 marker：`CI workflow run provenance contracts verified.`。

validator marker：`PASS verify_project ci workflow run provenance contracts`。

## 5. 非目标

- 不实现分类重命名、合并、删除、排序、最近使用或批量重分类。
- 不把搜索文本写入分类草稿，不新增模型字段、UserDefaults 键、迁移或第三方依赖。
- 不改变 v1.0/v1.1 的去重、任务计数、代表色、session-only 回退、草稿隔离和 selected 行为。
- 不修改 `TimerEngine`、计划生成、统计、StoreKit、EventKit、通知或跨页导航状态。
- 不改变 workflow artifact 名称、内容清单、manifest/index、retention、process version 或前三种 validator 兼容模式。
- validator 不联网、不读取 token；Run API JSON 仍由 Agent C 在包外获取。
- 不读取、编辑、暂存或提交 `md/1.md` 与 `md/通用云端迭代升级提示词.md`。

## 6. 架构与实现要求

### 6.1 iOS

- 在 `ChronoFocus/Views/ScheduleView.swift` 的 `TaskEditorView` 增加 View-only 搜索状态。
- 搜索 key 必须有独立 helper；空查询保持空字符串，禁止复用会把空分类转换为“未分类”的显示 helper。
- `filteredExistingCategoryOptions` 只能从稳定的 `existingCategoryOptions` 过滤。
- 搜索框、计数、清除和空态必须支持动态字体且不重叠；现有 chip 至少 44pt。

### 6.2 macOS

- 在 `ChronoFocusMac/Views/MacScheduleDetailView.swift` 实现同一阈值、folding、子串、计数与无结果语义。
- 真实搜索使用原生控件；静态快照使用快照安全控件，二者共享过滤 option，不复制业务算法。
- 外部分类预填路径清空搜索后再更新分类和聚焦，不自动保存。
- `scripts/render_mac_snapshots.swift` 种入至少 6 个非预设分类，并覆盖有结果搜索状态，不扩大正式快照清单。

### 6.3 Run 来源

- 在 `scripts/validate_ci_artifact.rb` 结构化校验四个字段；嵌套对象必须严格为 Hash，目标值必须严格为 String。
- 固定授权账号为 `Altman-sam114`，固定 head repository 为 `Altman-sam114/114`。
- 未提供 `--run-metadata` 的既有三种模式不输出或要求新增四项。
- 在 `scripts/verify_project.sh` 更新成功 fixture 和 `assert_run_metadata_passes_except`。
- 每个字段覆盖缺失、错误值和错误类型；嵌套对象还覆盖错误 shape/缺少目标子字段。每个负例必须保持三项 archive、八项 artifact metadata、其余 13 项 run metadata PASS，并且只让目标项 FAIL。
- 新增 provenance marker 缺失 fixture，只命中新项目契约 FAIL。

## 8. 云端验收

- GitHub Actions 执行静态检查、`bash scripts/verify_project.sh`、Mac core/snapshot、Mac build、iOS generic build和结果包上传。
- `verify_project.log` 必须包含 `Existing category search contracts verified.` 和 `CI workflow run provenance contracts verified.`。
- validator 必须输出 `PASS verify_project existing category search contracts`、`PASS verify_project ci workflow run provenance contracts`、14 项 Run metadata、8 项 artifact metadata和3项 archive。
- 预期基线至少 `128 PASS / 0 FAIL`（v1.1 的 122 项，加四项 Run 来源和两个项目 marker PASS），以云端实际数量为准，不提前冒充结论。
- Mac `detail-schedule.png` 必须覆盖长列表搜索状态，非空、无占位、无截断或重叠。
- Agent C 在全新唯一目录以 `.part` 无覆盖保存最新精确 Run API、Artifacts API 和 ZIP；核对 size、digest、ZIP、manifest、markers、Mac/iOS build、annotations 与完整日志。
- 只接受 `event=push`、actor/triggering actor 为授权账号、head repository 正确，且 branch/SHA/run/attempt 与最新 `origin/main` 完全一致的结果包。

## 9. 风险与停止条件

- 空查询被错误折叠成“未分类”会隐藏全部 option，必须由独立 helper 和云端契约阻止。
- macOS 持久页面旧查询可能隐藏外部预填分类，必须先清除查询。
- 正式验收将拒绝 workflow_dispatch；这与项目要求通过 push 触发一致。
- 失败不回滚，保留证据并由 Agent B 在 `main` 追加修复 commit；连续同因失败才按 Agent X 停止条件处理。

## 10. 完成标准

- 两端长分类列表可即时搜索、计数、清除并正确反馈无结果，所有搜索均为 View 瞬态。
- Run API 四项授权来源均结构化复判，旧模式保持兼容。
- 文档与真实实现同步，最新 `origin/main` 云端 run 成功且 Agent C 对原始证据复判为 0 FAIL 后，v1.2 才可闭环。

## 背景

`MacCalendarPanelView` 已经用 `visibleTasks` 计算当前日/周/月和可选分类筛选后的完整任务集合，日历范围标题也显示完整数量。但当前列表只渲染 `visibleTasks.prefix(4)`，当范围内有 5 项或更多任务时，用户无法知道还有隐藏项目，也没有展开入口。筛选分类、日期或范围变化后如果复用旧的展开状态，还可能让用户误解当前列表是否完整。

## 目标

1. macOS 日历范围列表默认显示前 4 项；当完整 `visibleTasks.count > 4` 时，提供明确的展开/收起操作，并显示准确的剩余数量或当前显示状态。
2. 展开/收起只改变列表的派生显示集合，不改变 `visibleTasks` 这个完整真源，也不改变日期格计数、范围总数、空态、分类筛选谓词、排序、任务操作或 `FocusStore` 数据。
3. `selectedCategory`、`selectedDate`、`calendarMode` 或完整结果的数量/身份发生变化时，展开状态恢复为收起，避免跨上下文残留。
4. 真实 macOS 交互和 `macSnapshotRendering` 静态快照路径保持同一可见数量、文案和分类上下文语义；正式 artifact 继续只保留既有五张 PNG。
5. 展开/收起控件满足至少 44pt 点击区、动态字体不截断关键数量、VoiceOver label/value/hint、Voice Control input labels，并在分类筛选时明确当前分类。

## 非目标

- 不修改 iOS 日程、计时页、共享模型、`FocusStore`、`TimerEngine`、持久化格式或 handoff 行为。
- 不改变日历日期格数字、`visibleTasks` 的日期范围规则、未截止任务规则、排序或任务操作。
- 不引入新的分类、筛选状态或计时状态，不把展开状态持久化。
- 不更改正式 artifact manifest 的五张快照清单、validator 的 archive 安全语义或 workflow artifact 结构。
- 不顺手拆分大型 View 文件或做无关 UI 重构。

## 当前架构依据

- `MacCalendarPanelView` 是 macOS 日程详情中的专用 SwiftUI 子视图，通过父级 `Binding<String?>` 接收 `selectedCategory`。
- `visibleTasks` 是当前范围和分类过滤后的完整数组；`calendarRangeCountText`、日期格计数和空态依赖完整集合。
- `MacTaskRowView` 负责单项展示；展开控件应留在日历面板的列表边界内，不把业务规则放入 `FocusStore`。
- `macSnapshotRendering` 只替换不稳定的原生控件为静态可见控件；静态控件仍需反映真实路径的标签、数量和分类语义。
- `scripts/verify_project.sh` 已输出 `Schedule calendar category context contracts verified.`，`scripts/validate_ci_artifact.rb` 已复判对应 `verify_project schedule calendar category context contracts`；优先扩展这份合同及其既有负向 fixture，不新增重复 marker。

## 实现步骤

1. 在 `MacCalendarPanelView` 增加私有、非持久化的展开状态，以及固定折叠阈值 4。
2. 从完整 `visibleTasks` 派生 `displayedTasks`：收起时取前 4 项，展开时取完整集合；所有计数、空态和日期格继续使用 `visibleTasks`。
3. 增加可展开/收起控件。超过 4 项时显示“显示其余 N 项”一类准确数量文案；展开后显示“收起”及当前显示状态。控件应使用熟悉的 chevron 图标和文字，不使用不可解释的纯图标。
4. 为控件提供稳定的最小 44pt 高度/点击区、适配 Dynamic Type 的布局、完整 VoiceOver label/value/hint，以及包含“展开/收起”、剩余数量、完整数量和当前分类的 Voice Control input labels。避免把数量放入可能被截断的固定宽度。
5. 在 `selectedCategory`、`selectedDate`、`calendarMode` 和完整结果身份/数量变化时将展开状态恢复为 false。若使用 `.onChange`，只监听能代表真实结果变化的值，避免在 View body 内做昂贵排序或重复过滤；不要把旧的展开状态保存到 `UserDefaults`。
6. 确认选择日期按钮将范围切到 day、左右导航、今天按钮和 segmented range 变化都会触发收起；分类切换也必须触发收起，即使新旧结果数量相同。
7. 更新 macOS 快照 fixture，使 `detail-schedule.png` 的云端运行数据在日历范围内至少有 5 项并可证明 overflow；正式日程快照使用足够显示任务列表、日历范围列表和展开入口的 1400pt 高画布。额外验证任务只允许在快照脚本 fixture 中使用，不改变正式五张文件名和 manifest entry 清单。快照应继续无黄色缺失控件、空白内容或明显文本截断。
8. 扩展 `scripts/verify_project.sh` 的现有日程日期格/分类上下文源码合同，验证完整数组、派生前 4/全部列表、重置接线、准确剩余数、44pt 和辅助功能语义；保持正向 fixture 只拥有一个目标合同。保留并增强只删除 `Schedule calendar category context contracts verified.` marker 的负向 fixture，确保只目标合同失败。
9. 由 Agent B 同步更新受影响的 `README.md`、`md/test/test.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`update_log.md` 和本提示词状态（只写当前真实行为、云端结果和遗留风险）。不要修改用户未跟踪文件 `md/1.md` 与 `md/通用云端迭代升级提示词.md`。

## 验收标准

- 收起时 0-4 项完整显示；超过 4 项时用户能看到准确隐藏数量并可展开全部，再次收起回到前 4 项。
- 切换分类、日期、日/周/月或完整结果变化后必定回到收起态；相同数量的新结果也不能继承旧展开态。
- 日历范围计数、日期格数字、空态和分类上下文始终来自完整 `visibleTasks`，不会因折叠而变小。
- 真实控件和快照控件拥有一致的动作文本、分类上下文、至少 44pt 点击区和 VoiceOver/Voice Control 语义。

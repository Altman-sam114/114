## 2. 背景

当前 `ChronoFocusMac/Views/MacTimerDetailView.swift` 的 `MacTaskQueueView` 具有以下真实行为：

1. `startableTasks` 从 `FocusStore.startableTasks()` 派生，`selectedCategory` 是 View 内的本地筛选状态。
2. `visibleTasks` 当前代表完整的分类筛选结果；未筛选时是全部可启动待办，筛选时按 `task.category == selectedCategory` 过滤。
3. 空态、`MacTimerCategoryContextView` 的筛选数/总数以及队列标题使用完整结果；真正渲染任务行时才调用 `visibleTasks.prefix(7)`。
4. 分类筛选任务行通过 `TimerEngine.selectTask(_:)` 选择，运行中由行上的 `.disabled(engine.isRunning)` 和 guard 阻止切换；当前任务的 selected trait、任务名/分类名 Voice Control input labels 和“计时运行中不可切换当前待办”提示已经存在。
5. `MacTaskRowView` 同时被 Mac 计时队列和 `MacScheduleDetailView` 复用。计时队列筛选态传入 `showsCategoryBadge: false` 以避免重复视觉 badge，但整行辅助功能语义必须保留；日程调用使用默认 `showsCategoryBadge = true`，不能被本轮破坏。
6. iOS `TimerView` 已有 v0.99 的队列展开模式：按完整筛选结果派生显示列表，分类和筛选结果数量变化时恢复收起，运行中仍可展开浏览但任务行不可切换。本轮借鉴该状态边界和辅助功能语义，但 macOS 阈值必须保持当前产品规则的 7 项，而不是复制 iOS 的 4 项。

本轮的重点是把 Mac 队列的“完整筛选结果”和“当前可见前缀”明确分开，避免展开后把分类上下文条或队列计数错误显示成 7 项；同时让展开按钮本身在 VoiceOver 和 Voice Control 下可被理解和操作。

## 3. 目标

### 3.1 队列展示

- 增加仅属于 `MacTaskQueueView` 的临时 `isTaskQueueExpanded` 状态，默认值为 `false`。
- 保留 `collapsedTaskLimit = 7`。筛选结果为 0 至 7 项时显示全部结果且不显示展开控制；超过 7 项时默认只显示前 7 项。
- 展开后显示当前完整筛选结果；收起后恢复前 7 项。
- 展开控制只控制任务行显示数量，不改变 `selectedCategory`、当前任务、`TimerEngine` 状态、任务顺序、`FocusStore` 数据或持久化内容。
- 展开/收起控制只在完整筛选结果数量大于 7 时出现，剩余数必须是 `max(filteredTasks.count - 7, 0)` 的动态值，不能写死。

### 3.2 分类切换和数量变化重置

- `selectedCategory` 发生任何变化时把 `isTaskQueueExpanded` 恢复为 `false`，覆盖点击分类、再次点击已选分类、点击“全部”、上下文条清除和日程接力恢复分类等入口。
- 完整筛选结果的 `count` 发生变化时也把 `isTaskQueueExpanded` 恢复为 `false`，覆盖新增、完成、删除、启用/停用或其他 `FocusStore` 更新导致的当前结果数量变化。
- 重置必须通过对状态值和完整筛选结果数量的 `.onChange` 接线实现，不能只在某个分类 chip 或清除按钮的 action 中手动重置。
- 重置只影响展开状态；不得清除分类、改变当前任务、停止计时、自动选择其他任务或修改持久化模型。

### 3.3 运行中边界

- 计时运行中仍可点击展开/收起，以便只读浏览完整队列。
- 计时运行中所有任务行继续禁用，不能通过展开后新增的任务行切换当前待办。
- 展开控制不得位于带有 `.disabled(engine.isRunning)` 的父容器中，也不得自身使用该禁用条件。
- 非运行状态的任务选择、selected trait、当前任务上下文和既有 `TimerEngine.selectTask(_:)` 接线保持不变。

### 3.4 VoiceOver / Voice Control

展开控制必须是一个清晰的按钮元素，提供两种状态的可见文案和辅助功能语义。动态数字必须来自当前完整筛选结果，不能缓存旧分类或旧数量。

- 收起状态的可见标题为 `显示其余 N 项`，其中 `N` 是当前剩余数量；VoiceOver label 至少表达 `显示其余N项待办`。
- 收起状态的 VoiceOver value 至少表达 `已收起，显示 7 项，共 M 项`，其中 `M` 是完整筛选结果数。
- 收起状态的 VoiceOver hint 至少表达 `展开后可查看其余 N 项待办`；运行中追加 `计时运行中待办仍不可切换` 等价明确提示。
- 展开状态的可见标题为 `收起`；VoiceOver label 至少表达 `收起待办列表`。
- 展开状态的 VoiceOver value 至少表达 `已展开，显示全部 M 项`。
- 展开状态的 VoiceOver hint 至少表达 `收起后仅显示前 7 项待办`。
- 两种状态的 `accessibilityInputLabels` 都必须把当前可见标题作为第一项。收起状态至少包含 `显示更多待办`、`显示更多`、`展开待办`；展开状态至少包含 `收起待办`、`收起待办列表`。
- toggle 的图标、可见文字和按钮不能形成 VoiceOver 重复朗读；显式 label/value/hint/input labels 必须作用于同一个按钮。
- 控件点击高度至少 44pt，允许动态字体和长数字/长分类上下文换行，不得靠截断、负向 letter spacing 或遮挡来解决布局问题。
- 现有分类上下文条、分类 chip、任务行的分类名、任务名、selected trait、运行中提示和 Voice Control labels 必须继续存在；隐藏视觉 badge 不能隐藏这些辅助功能语义。

## 5. 当前架构依据

### 5.1 状态与数据边界

- `FocusStore.startableTasks()` 是 Mac 计时队列的唯一可启动待办来源。当前筛选结果仍在 View 中派生，不新增 Store API。
- `TimerEngine` 是唯一计时状态机。任务行选择必须继续调用 `engine.selectTask(task)`，运行中不能改变 `selectedTaskID`；展开控制不得调用 `start()`、`pause()`、`resume()`、`stop()` 或任何计时接口。
- `MacTaskQueueView` 可以持有 `@State` 展示状态，但该状态只在 View 生命周期内有效，不参与跨页接力请求，不写入持久化。
- `MacTimerCategoryContextView` 的 `filteredCount` 必须接收完整筛选结果数，而不是收起状态下可见的 7 项；分类空态判断也必须基于完整筛选结果。
- `MacScheduleDetailView` 的 `MacTaskRowView(task: task)` 依赖默认参数显示分类 badge。本轮如果调整任务行，必须保持 `var showsCategoryBadge = true` 和默认调用兼容。

### 5.2 目标数据流

```text
FocusStore.startableTasks()
  -> filteredTasks（按 selectedCategory 过滤，保留完整结果）
  -> filteredTasks.count（队列计数、分类上下文、空态、toggle 条件）
  -> visibleTasks
       isTaskQueueExpanded ? filteredTasks : Array(filteredTasks.prefix(7))
  -> ForEach(visibleTasks) 只渲染当前可见任务行
  -> 展开/收起按钮只修改 isTaskQueueExpanded

selectedCategory 变化或 filteredTasks.count 变化
  -> isTaskQueueExpanded = false
```

不要把 `visibleTasks` 的截断结果重新用于分类上下文、空态或筛选计数；不要把 `filteredTasks.count` 变化监听写成只观察当前可见前缀的数量。

### 6.2 Mac 队列状态和派生值

### 6.3 展开/收起按钮

1. 使用独立的计算属性集中提供可见标题、VoiceOver label、value、hint 和 Voice Control input labels，所有动态数值都从当前 `filteredTasks` 派生。

3. 使用 chevron 等已有 SF Symbol 表达两态，保留文字标题；按钮至少有 `.frame(maxWidth: .infinity, minHeight: 44)`、合理的 `contentShape` 和可换行布局。
4. 不给该按钮加 `.disabled(engine.isRunning)`。若 snapshot rendering 需要静态控件，静态分支也必须保留可见标题和两态 accessibility modifiers，不能渲染黄色缺失控件占位或另持有一套状态。
5. 保持已有 Mac 视觉规范：使用现有 `currentTint`/按钮样式、最多 8px 圆角或现有胶囊样式；不要为了放入长文案而压缩到不可读或与任务行重叠。

### 6.4 分类和数量变化重置

1. 在 `MacTaskQueueView` 根视图上对 `selectedCategory` 增加 `.onChange`，其 action 必须设置 `isTaskQueueExpanded = false`。
2. 对完整 `filteredTasks.count` 增加独立 `.onChange`，其 action 必须设置 `isTaskQueueExpanded = false`。
3. 既有 `consumeTimerHandoffRequest()` 恢复分类时可以显式设置收起作为即时保护，但不能以此替代上述两个状态观察；分类清除、Store 更新和非接力路径也必须自动收起。

## 10. 验收标准

### 10.1 UI 和状态行为

- 0 项：保留现有通用空态或分类空态，不显示展开/收起按钮。
- 1 至 7 项：全部显示，不显示无意义的 toggle。
- 8 项及以上：默认显示前 7 项，并显示准确的 `显示其余 N 项`；展开后显示全部当前筛选结果并显示 `收起`；再次收起恢复前 7 项。
- 未筛选和分类筛选都遵守同一阈值；分类筛选后的完整结果数大于 7 时也必须可展开。
- 切换分类、再次点击已选分类退出筛选、点击全部、上下文清除、接力恢复分类后，队列恢复收起；即使新旧分类数量相同也不能保留旧展开状态。
- 当前完整筛选结果数量变化后恢复收起；队列计数、分类上下文条和空态仍基于完整结果，不显示截断后的错误数量。
- 运行中可以展开/收起并浏览；所有任务行仍不可切换，当前任务和 `ActiveTimerSnapshot` 不变。
- 非运行状态选择任务的既有行为、排序、分类 badge 隐藏/显示规则、日程页面复用行为均不回归。

### 10.2 可访问性

- toggle 在收起/展开两态都有正确的可见标题、VoiceOver label、value、hint 和 Voice Control input labels；动态剩余数和总数准确。
- Voice Control input labels 两态都以当前可见标题开头，并包含约定的 `显示更多待办`/`显示更多`/`展开待办` 或 `收起待办`/`收起待办列表`。
- toggle 至少 44pt，动态字体和长文本可换行，文字、图标、按钮和任务行不遮挡或截断到不可辨认。
- 运行中 toggle 仍可访问；任务行继续保留 selected trait、任务/分类 Voice Control labels 和不可切换提示。
- 筛选态隐藏的是重复视觉分类 badge，不是任务行的分类辅助功能语义；Mac 日程任务行默认分类 badge 和语义保持。

### 10.3 CI 和文档

- 现有 `Mac timer category queue contracts verified.` marker、validator PASS 和 marker 缺失负向 fixture 继续有效，并覆盖本轮新增的 Mac queue 源码条件。
- 最新云端的 Static checks、Project verification、Mac core、Mac build、iOS generic build、snapshot、artifact upload 和 Final CI status 全部成功；不接受本地命令结果替代。
- 最新 artifact 的 `branch=main`、`commitSha`、run id、run attempt、artifact name、API size/digest 与 `origin/main` 最新状态完全一致；完整第四模式复判通过。
- 正式 artifact 清单、artifact schema、workflow 和 CI Action 版本没有无关变化；额外 overflow 快照只作为运行期检查，不进入正式 manifest。
- README、`update_log.md`、`md/test/test.md`、`md/flow/flow.md`、`md/flow/flowchart.md` 和 `md/prompt/README.md` 与真实行为和最终云端结果一致；云端通过前不写虚假结论。

## 11. 风险

- 若继续在 `ForEach(visibleTasks.prefix(7))` 中截断，而不分离完整 `filteredTasks`，展开逻辑、hidden count、分类上下文和数量提示会互相矛盾。
- 若用 `visibleTasks.count` 或可见前缀监听数量，新增/删除后可能无法重置，或者 7 项与 8 项之间产生错误状态；必须监听完整筛选结果 count。
- 若只在分类按钮 action 中重置，摘要清除、接力恢复和 Store 更新会漏掉；必须保留两个 `.onChange` 观察源。
- 若把 `.disabled(engine.isRunning)` 放在包含 toggle 的 `VStack`/父按钮，运行中无法展开；禁用边界只能覆盖任务行。
- 若把展开状态放入 `FocusStore` 或复用 `TimerEngine`，会产生不必要的持久化/计时耦合，并可能跨页面恢复错误状态。
- 若隐藏 badge 时连同 accessibility modifiers 一起移除，会回归任务分类、selected trait、VoiceOver 和 Voice Control 合同。
- 快照 fixture 任务过多可能让 Mac 日程或计划面板内容溢出；应使用短标题、独立分类和运行期额外图，保留现有产品接力快照，不扩大正式 artifact。
- 源码合同如果依赖从任意位置截取的大段文本，后续轻微 helper 调整就会误报；应沿用现有 `segment_slice` 稳定声明边界，并让失败信息指向具体缺失条件。
- GitHub API 的 artifacts response 不直接提供 `run_attempt`；不能把包内字段当成包外来源，也不能用旧 run 的 artifact 名称或 digest 冒充新证据。

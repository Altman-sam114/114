# v1.5：计时与日程信息层级

## 版本、状态与分配依据

- 版本：`v1.5`；在 v1.4.9 分类搜索后进入可见界面改进轮，不继续用单个辅助功能 marker 代替产品体验工作。
- 提示词日期：2026-10-13；静态设计基线为 `a1817e4`。设计可并行，实现必须等待 v1.4.8 基线修复和 v1.4.9 最新云端闭环；A 的文件落盘不代表这些前置已通过。
- 建议提交信息：`v1.5: 优化计时与日程信息层级`。必要修复继续 v1.5 追加提交，不回滚、不把未来轮次混入本轮。
- 本轮只聚焦 iOS/macOS 计时与日程的首屏、主控、任务优先级及紧凑布局。不是全 App 重写，也不是发布资质验收；Mac 浅色主题、首次启动数据、日历权限与 iOS 运行测试基建均明确列为后续独立轮次。
- 本提示词由 A 设计并交 X 调度；不得为提交未来提示词而使正在验收的 v1.4.8 SHA 变化。整合 B 仅在对应轮次纳入本文件。

## 背景与静态证据

1. `TimerView.body` 目前依次渲染 header、modePicker、圆盘、主控、只设开始完成按钮、完整提醒面板、任务队列、通知/铃声信息块。大圆盘内又有三项统计，使“选待办后开始”与提醒配置竞争首屏空间；停止、跳过、开始都是图标，用户需猜动作。
2. `ScheduleView.body` 把日历同步和整个番茄计划放在 taskList 前，日常“查看/新增/开始待办”反而被次要功能推远。
3. `MacTimerDetailView` 两列分别有 420pt 和 320pt 最小宽度，再加 18pt 间距、48pt 页边距与至少 190pt 侧栏；详情窗口最小宽度却是 920pt，现有下限不足以容纳这些刚性约束。宽画布渲染不能证明最窄真实窗口可用。
4. `MacScheduleDetailView` 真实路径把 taskListPanel 放在日历/同步/计划之后，快照路径却放在前面；1400pt 截图中任务可见不代表真实首屏排序相同。这是本轮必须消除的渲染/产品布局差异。
5. 当前已具有正确分类来源、active snapshot、handoff 和大部分 VoiceOver/Voice Control 语义。应重新组织真实组件而不是丢掉这些能力或重新实现核心状态机。

## 目标与非目标

目标：

- 首次看到计时页就能识别“当前任务、剩余时间、开始/暂停/继续”；日程页优先呈现日期、分类和待办，而非配置/同步。
- 把主要操作变成明确的文字加图标按钮，次要动作弱化但不隐藏，保留不误触和原有语义。
- iOS 大字体优先换行和纵向重排，macOS 在真实 920pt 窗口与常规 1100pt 窗口都能完整访问内容，不用扩大最小窗口掩盖问题。
- 正式云端快照与真实界面使用同一内容顺序；通过真实 core 断言、双端 build、云端渲染和 C 的视觉核对验收本轮，不把源码搜索当成全部测试。

非目标：

- 不改 TimerEngine 计时状态机、自动流转、持久化结构、StoreKit、EventKit、Live Activity 或通知策略；不复制核心逻辑。
- 不新增品牌字体/图片/第三方 UI 库，不引入 iOS 26 专属 API。沿用现有青绿强调色、圆角、原生 SwiftUI 和系统可缩放排版，保留最低系统兼容性。
- 不删除任务、分类、统计、提醒或现有用户可访问功能；低频面板可折叠，但入口必须可见且文案准确。
- 不实现分类重命名/合并、系统权限修复、演示数据迁移或全 App 主题切换。这些是明确下一轮目标，不顺手混入。
- 不宣称五张 Mac ImageRenderer 截图等于 App 端到端 UI 测试，不宣称 iOS generic build 已验证 Dynamic Type 实机/模拟器渲染。
- 不改变 CI process version、生产 artifact 命名、七业务阶段、JUnit 四 testcase、正式五张 PNG 与既有 archive/API 安全规则。生产源 run 必须仍恰好一个 artifact；新增辅助视觉证据走单独命名的 workflow/run，不在生产 run 上传第二包，也不塞入旧精确 allowlist。

## 架构与状态所有权

- `FocusStore` 仍是唯一数据仓库；`TimerEngine` 仍是唯一开始、暂停、恢复、停止、跳过、完成入口。
- 当前任务标题、分类、颜色在运行/暂停时从 `store.activeTimer` 读取；空闲才回到选择任务/自由专注。重排不能改变保护、选择和 handoff 语义。
- 提醒面板展开状态、紧凑布局选择和 View 视觉状态归对应 View 的 `@State` / 环境值；不写入 UserDefaults，不进入 FocusStore，不新建 view model。
- 已有 iOS 四 Tab 与 Mac `MacDetailSelection` 保持不变；分类搜索/筛选、selected retention、展开队列、日期上下文和快捷新增复用 v1.4.9。
- 可在原文件按职责提取小 View/helper 以缩短 SwiftUI 类型推断，但只围绕本轮组件。新文件如有必要必须接入对应 target；不要整仓 Observation 迁移或创建泛化设计系统。
- 实现沿用仓库现有 SwiftUI 布局与平台边界；此前引用的 `build-ios-apps:swiftui-ui-patterns` 不在当前可用技能目录，不作为依赖。所有 build/preview 验证均由 GitHub Actions 执行，本地禁止项不变。

## 实现要求

### 1. iOS 计时首屏与主控

- 首屏信息顺序收敛为“当前任务/阶段 -> 模式与倒计时 -> 主要动作 -> 当前待办队列 -> 低频提醒与统计”。header 的“智能专注中枢”营销式副标题可改为短状态或去掉，但当前任务与轮次不能丢。
- 倒计时继续是视觉重点，但从现有最大 330pt 圆盘和固定 62pt 字体中解耦：使用可缩放字体/尺寸、可用宽度与 Dynamic Type 判断，常规窄屏保持主按钮尽量在首屏，大辅助字体使用直线/紧凑计时摘要或纵向布局，不把文字无限缩小塞进圆环。
- 主按钮明确显示 `开始专注` / `暂停` / `继续`，休息模式显示相应“开始休息”等准确文案；动作仍直接调用既有 `engine.start/pause/resume`。停止与跳过显示文字和图标，以次级样式分离；不能让三个按钮视觉权重相同。只设开始任务的“完成当前待办”入口保持可见和现有行为。
- 44pt 是实际 Button label 命中区域要求，不只是外层空 frame。Dynamic Type 达辅助字体时改为纵排或自适应多行，避免固定 `.frame(height: 58)` 剪裁按钮文字；动作控件不通过 `minimumScaleFactor` 压小辅助字体。
- “提醒与屏幕”默认折叠，标题旁可展示真实静音/音量和常亮摘要；点击展开仍访问现有音量、振动、常亮设置，音量为 0 与 soundEnabled 的联动原样保留。折叠 header 自身是有 label/value/hint 的按钮，状态改变不影响计时。
- 将 taskPicker 放到完整提醒控制之前；圆盘下三项统计与底部通知/铃声信息可合并降为一行次级摘要，避免重复强调同一状态。不得在纯空列表状态移除自由专注开始能力。
- 选中任务时标题/分类可读，长任务名允许自然换行；保留主控任务与分类的可访问标签/输入标签，不用短视觉标题覆盖完整语义。

### 2. iOS 日程任务优先

- 真实顺序为日历 -> 分类与待办 -> 计划/同步等辅助区域。分类搜索与当前范围计数靠近列表，不因重排改变 countProvider 的日期范围。
- toolbar 的新增入口由仅加号改为清楚的“新增”加图标，仍使用当前日期和选中分类预填；保留 accessibilityLabel/hint/inputLabels。
- 计划面板、同步面板可以保持完整，只需放到待办之后；本轮不强行引入更多折叠 state。若实际长列表导致辅助功能无法访问，保留既有队列折叠或采用明确展开入口，不截断内容。
- 任务行、分类摘要、日期格、空态及 handoff 不复制实现；大字体下摘要标题与动作纵排，不能为了首屏密度降低44pt点击区或隐藏任务完成/编辑入口。

### 3. macOS 紧凑布局与真实/快照一致

- `MacTimerDetailView` 根据内容区实际可用宽度切换两列/单列，可用 `ViewThatFits` 或语义明确的布局分支；横向分支的 minWidth 不得继续强迫920pt窗口溢出。不要只依据屏幕宽度或把窗口 minSize 改到更大。
- 常规1100pt窗口保留“计时主区 + 今日/待办侧栏”，紧凑920pt窗口在侧栏占宽后自动转单列，计时主区优先且队列可垂直滚动；不新增嵌套横向滚动来掩盖溢出。
- 计时主控保持文字、图标和主次层级，运行、暂停、空闲以及只设开始完成动作在真实和静态安全路径完全一致；使用同一标题派生规则，不另写快照专属业务状态。
- `MacScheduleDetailView` 真实路径与快照路径都把待办面板放在同一位置，且先于同步/计划。`isSnapshotRendering` 只能替换无法渲染的原生控件，不能再调整产品内容顺序。
- 如日程左右列在920pt窗口不能容纳，允许同样单列重排；保留快速新增的分类预填、标题FocusState、日期时分和连续新增分类。不要把320pt固定表单挤压到页面外。
- MacMini 保持430/560pt popover现有行为；不是本轮重做目标。若共享组件受影响，应继续通过500pt高度快捷面板、滚动与44pt既有回归。
- 不在本轮移除 `.preferredColorScheme(.dark)` 后假装支持浅色。MacTheme、硬编码白色背景/文字和全部页面的主题适配另列v1.5.1，避免半个窗口浅色半个深色。

## 背景

ChronoFocus 目前把分类颜色分散在预设元数据、待办自身 `accentHex`、历史会话和 View 内 fallback 中。预设分类通常一致，但同一个自定义分类在任务行、分类筛选 chip、筛选摘要/空态、计时任务队列、计划项和 macOS 小窗中可能显示不同颜色；仅有历史会话的分类也可能退回统一青色。任意合法 HEX 还可能让选中控件的固定黑字失去对比度，运行中编辑待办也可能让 UI 重新读取任务色而偏离已持久化计时快照。现有 `FocusStore` 已拥有任务、会话和分类顺序，适合提供非持久化、稳定的分类代表色查询。

## 目标

1. 在共享模型/仓库建立单一的分类代表色规则：预设分类使用预设色；非预设分类优先使用该分类首次出现的任务色；没有任务颜色的历史分类使用统一 fallback。分类比较至少保持现有去空白语义，并不得新增持久化字段。
2. iOS 与 macOS 的分类筛选、摘要、空态、待办行、计划项、计时当前任务/队列和已有分类复用入口使用同一代表色；同一分类在不同平台和不同入口不再因 View 局部 fallback 产生颜色漂移。保留任务编辑器可选颜色和预设分类图标行为。
3. 对选中分类背景使用共享对比文字颜色，覆盖自定义深色/浅色 HEX、iOS/macOS chip 和日期格；计时运行中优先显示 `ActiveTimerSnapshot.tintHex`，避免编辑任务后主计时 UI 与 Live Activity 颜色分裂。
4. 增加云端可执行的 core/static 合同和独立 marker，覆盖预设优先级、任务优先于 session、session-only、fallback、HEX 清洗/对比度和运行中快照色规则；负向 fixture 只破坏该合同，不放宽现有 CI artifact 成功验收。

## 非目标

- 不改变 `FocusTask`、`FocusSession`、`PomodoroPlanItem` 或 `ActiveTimerSnapshot` 的 Codable 字段和 UserDefaults 格式。
- 不改变分类名称、筛选排序、计划生成、StoreKit、EventKit 或日历同步业务语义；TimerEngine/通知/Live Activity 只允许为活动快照颜色一致性、暂停恢复、设置开关和运行中任务锁定补充表面同步/清理，不得新增计时状态机或改变自动流转规则。
- 不删除历史实现、用户文件、快照资源或已有 CI fixture；不新增第三方依赖，不改 `md/1.md` 或 `md/通用云端迭代升级提示词.md`。
- 不把自定义分类改成可独立持久化的设置实体；代表色只从现有任务/会话数据派生。

## 当前架构依据

- 共享模型为 `ChronoFocus/Models/AppModels.swift`，共享数据仓库为 `ChronoFocus/Services/FocusStore.swift`。
- iOS 分类 UI 主要位于 `ChronoFocus/Views/ScheduleView.swift`、`TimerView.swift`、`AnalyticsView.swift`；macOS 分类 UI 主要位于 `ChronoFocusMac/Views/MacScheduleDetailView.swift`、`MacTimerDetailView.swift`、`MacMiniTimerView.swift`、`MacAnalyticsDetailView.swift`。
- `TaskCategoryPreset.prioritizedFilterOptions` 是 iOS/macOS 分类筛选的共同排序入口；`FocusStore.categoryBreakdown()` 是统计颜色的共享来源。
- CI 只由 `.github/workflows/ci-results.yml` 触发，`scripts/test_mac_core.swift` 执行共享 core 合同，`scripts/verify_project.sh` 执行静态/项目合同，结果包由 `scripts/validate_ci_artifact.rb` 复判。

# v1.4.8：自定义分类代表色统一

## 版本与分配依据

- 分配依据：v1.4.7 已完成 CI 失败结果包韧性实现，正常 push run `32637110761` 已通过；受控 `workflow_dispatch` run `32637443128` 已生成可追溯失败包，待记录后进入下一轮产品 UI 优化。

## 背景

ChronoFocus 目前把分类颜色分散在预设元数据、待办自身 `accentHex`、历史会话和 View 内 fallback 中。预设分类通常一致，但同一个自定义分类在任务行、分类筛选 chip、筛选摘要/空态、计时任务队列、计划项和 macOS 小窗中可能显示不同颜色；仅有历史会话的分类也可能退回统一青色。任意合法 HEX 还可能让选中控件的固定黑字失去对比度，运行中编辑待办也可能让 UI 重新读取任务色而偏离已持久化计时快照。现有 `FocusStore` 已拥有任务、会话和分类顺序，适合提供非持久化、稳定的分类代表色查询。

## 目标

1. 在共享模型/仓库建立单一的分类代表色规则：预设分类使用预设色；非预设分类优先使用该分类首次出现的任务色；没有任务颜色的历史分类使用统一 fallback。分类比较至少保持现有去空白语义，并不得新增持久化字段。
2. iOS 与 macOS 的分类筛选、摘要、空态、待办行、计划项、计时当前任务/队列和已有分类复用入口使用同一代表色；同一分类在不同平台和不同入口不再因 View 局部 fallback 产生颜色漂移。保留任务编辑器可选颜色和预设分类图标行为。
3. 对选中分类背景使用共享对比文字颜色，覆盖自定义深色/浅色 HEX、iOS/macOS chip 和日期格；计时运行中优先显示 `ActiveTimerSnapshot.tintHex`，避免编辑任务后主计时 UI 与 Live Activity 颜色分裂。
4. 增加云端可执行的 core/static 合同和独立 marker，覆盖预设优先级、任务优先于 session、session-only、fallback、HEX 清洗/对比度和运行中快照色规则；负向 fixture 只破坏该合同，不放宽现有 CI artifact 成功验收。

## 非目标

- 不改变 `FocusTask`、`FocusSession`、`PomodoroPlanItem` 或 `ActiveTimerSnapshot` 的 Codable 字段和 UserDefaults 格式。
- 不改变分类名称、筛选排序、计划生成、StoreKit、EventKit 或日历同步业务语义；TimerEngine/通知/Live Activity 只允许为活动快照颜色一致性、暂停恢复、设置开关和运行中任务锁定补充表面同步/清理，不得新增计时状态机或改变自动流转规则。
- 不删除历史实现、用户文件、快照资源或已有 CI fixture；不新增第三方依赖，不改 `md/1.md` 或 `md/通用云端迭代升级提示词.md`。
- 不把自定义分类改成可独立持久化的设置实体；代表色只从现有任务/会话数据派生。

## 当前架构依据

- 共享模型为 `ChronoFocus/Models/AppModels.swift`，共享数据仓库为 `ChronoFocus/Services/FocusStore.swift`。
- iOS 分类 UI 主要位于 `ChronoFocus/Views/ScheduleView.swift`、`TimerView.swift`、`AnalyticsView.swift`；macOS 分类 UI 主要位于 `ChronoFocusMac/Views/MacScheduleDetailView.swift`、`MacTimerDetailView.swift`、`MacMiniTimerView.swift`、`MacAnalyticsDetailView.swift`。
- `TaskCategoryPreset.prioritizedFilterOptions` 是 iOS/macOS 分类筛选的共同排序入口；`FocusStore.categoryBreakdown()` 是统计颜色的共享来源。
- CI 只由 `.github/workflows/ci-results.yml` 触发，`scripts/test_mac_core.swift` 执行共享 core 合同，`scripts/verify_project.sh` 执行静态/项目合同，结果包由 `scripts/validate_ci_artifact.rb` 复判。

## 实现步骤

1. 同步最新 `origin/main`，静态审阅相关模型、仓库、iOS/macOS View 和现有 CI marker；只保留本轮必要 diff。
2. 在共享模型提供统一 fallback/预设代表色入口，并在 `FocusStore` 提供按现有任务/会话顺序派生代表色的非持久化查询。明确非法/空色值的 fallback 行为，避免 View 各自硬编码规则。
3. 让分类筛选 option 接受共享代表色提供者；更新 iOS/macOS 筛选 chip、摘要/空态、任务行、计划项、计时当前任务/队列、macOS 小窗和已有分类复用的颜色来源。保持 44pt 操作区、VoiceOver/Voice Control 文案和现有快照安全控件边界。
4. 在 `scripts/test_mac_core.swift` 增加四种代表色、HEX 清洗、对比度和运行中快照色正向断言；在 `scripts/verify_project.sh` 增加有边界的源码合同、正向 marker 和仅目标失败的 negative fixture；同步 validator 的预期 marker/PASS 和 fixture allowlist。不得以宽泛字符串计数替代阶段/文件边界检查。
5. 同步 `md/test/test.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`README.md`、`md/prompt/README.md` 和 `update_log.md`。文档中的验证结果只能填写实际云端 run/artifact，不得填写本地测试结果。
6. CI 结果包的 finalizer 失败时，使用 `scripts/recover_ci_result_package.py` 在上传前重建 fallback 的 run context、stage outcomes、manifest、summary、JUnit 和 index；上传条件必须要求正常 finalizer 或恢复步骤成功，不能上传陈旧成功目录。成功包 required 路径缺失必须让 finalizer 失败，recovery 缺少六项核心证据必须直接失败；fallback artifact 名称由 branch slug 统一派生，validator 逐项绑定阶段摘要 outcome，并以 skipped-only negative fixture 拒绝没有真实失败阶段的伪失败包。manifest/JUnit 使用归一化 outcome，validator 绑定 index/summary 的 package stage 状态，并覆盖新增恢复接线。
7. 提交信息使用 `v1.4.8: 统一自定义分类代表色`，确认只提交本轮相关文件后推送 `origin/main`。Agent C 只用 `gh` 获取最新 push run 的原始 run/artifacts API JSON、唯一 ZIP 和未加密结果包，复核 manifest、JUnit、日志、两端 build、五张正式快照和代表色 marker；失败则在 `main` 追加最小修复 commit。

## 验收标准

- 自定义分类在 iOS/macOS 的筛选 chip、选中摘要、空态、任务行、计划项、计时任务和已有分类复用入口均使用同一代表色；预设色优先，任务优先于历史会话，session-only 可稳定显示，空分类使用统一 fallback；选中背景文字按共享对比度规则选择。
- Mac 快捷面板在 500pt popover 内由快照环境确定性显示并可垂直滚动；iOS/macOS 计划、筛选摘要、日历导航和待办操作的真实控件与静态占位均提供至少 44pt 命中区。
- 运行中任务编辑或删除后，iOS/macOS 主计时 UI 仍使用活动快照的 `tintHex`，与 Live Activity/恢复数据保持一致。
- 代表色查询不写入 UserDefaults，不改变既有 Codable 解码和核心状态机；旧数据缺字段仍可读取。
- 云端 `Project verification` 输出代表色 resilience marker、CI failure artifact resilience marker，Mac core 正向断言通过，required 缺失、阶段摘要篡改和 skipped-only 负向 fixture 只出现目标 `FAIL`；静态、双端 build、JUnit、manifest/index/run context、五张快照和 artifact 第四模式全部通过。
- 最新 `origin/main` push run 的 `head_sha`、branch、run attempt、artifact API、原始 ZIP 和 manifest 完全一致；未完成 Agent C 复判前不得宣布本轮通过或总目标完成。

## 风险和禁止项

- 任务数组顺序是当前唯一的自定义代表色来源顺序，不能未经说明改为按名称或数量排序，否则会造成历史 UI 颜色漂移；无任务颜色的历史分类必须回到统一 fallback。
- 不能让预设分类被自定义任务颜色覆盖，也不能在单个平台继续保留独立 fallback。
- 禁止修改或删除用户未跟踪文件、历史证据、正式快照和其他 Agent 改动；禁止本地测试/validator/Xcode/浏览器；禁止使用其他 GitHub 账号、旧 run/artifact 或文字汇报冒充最新云端证据。
